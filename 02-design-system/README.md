# Дизайн-система

Всё про саму систему: что это, из чего состоит, где что лежит и как этим пользоваться. Правила применения компонентов — в [`сборка-из-ДС.md`](сборка-из-ДС.md).

## Что это

Дизайн-система iiko — это библиотека компонентов и токенов, по которой собираются интерфейсы: одна кнопка, одно поле, одно состояние на весь продукт. Из неё собираются прототипы (см. [`../03-prototypes/`](../03-prototypes/)), и она же — источник истины про внешний вид: если макет и система расходятся, верна система.

## Из чего состоит

| Часть | Где лежит |
|---|---|
| Спецификация: какие бывают варианты, состояния, классы | `iiko-ds-web/iiko-ds-spec.md` |
| Токены: цвета, размеры, отступы, типографика | `iiko-ds-web/tokens.css` |
| Компоненты десктопа: разметка и стили | `iiko-ds-web/components/<Имя>_DS/*.css`, общий индекс — `components/index.css` |
| Правки поверх генерации библиотеки | `iiko-ds-web/fixes.css` |
| Мобильный слой: компоненты и режимы | `iiko-ds-mobile/components/…`, `iiko-ds-mobile/modes.css` |
| Данные страниц компонентов | `_audit/rec/data/<компонент>.json` |
| Технические заметки: источники, платформа, замеры | `_audit/rec/data-tech/<компонент>.json` |
| Мобильные значения компонента | `_audit/platform/<компонент>.json` |
| Страницы компонентов для просмотра | генерируются в `iiko-ds-mobile/prototypes/recommendations/` — руками не правятся |

## Как этим пользоваться

1. **Сначала спецификация, потом вёрстка.** Перед сборкой блока читаем `iiko-ds-spec.md`: там написано, какие варианты и состояния у компонента есть и как называются классы.
2. **Берём компонент и его переменные**, а не рисуем своё: классы `ds-*`, токены `--ds-…`.
3. **Состояния — из системы:** Default / Hover / Press / Selected / Disable, не свои цвета и тени.
4. **Иконки** — Material Icons по имени, семейство Outlined; фирменные глифы — выгрузкой из макета.

Правила применения подробно — [`сборка-из-ДС.md`](сборка-из-ДС.md).

## Границы: чего в системе нет

Если компонента в системе нет — это **пробел системы**, а не повод написать свой стиль на странице. Порядок такой: собрать из ближайшего подходящего компонента, пометить в коде `/* косяк ДС: … */` и записать в список замечаний, чтобы система когда-нибудь получила этот компонент по-настоящему.

## Где посмотреть результат

Страницы компонентов собираются локально: `python start.py` в папке `DS` (подробности — [`../01-start/`](../01-start/)). Там же форма ревью: решения по компонентам сохраняются файлами в `_audit/rec/review/<компонент>.<имя>.json`.

Разборы и замеры по системе — в [`../07-research/`](../07-research/), принятые решения — в [`../08-decisions/`](../08-decisions/).
