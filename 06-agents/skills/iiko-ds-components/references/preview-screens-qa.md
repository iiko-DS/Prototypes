# Приёмка блока «На экране» — три экрана, главный компонент, ничего не сломано (13.09.2026)

Финальный прогон разлива формата страниц. Платформенные колонки встали на все 38 страниц,
`audit-edits.py` довёл поля «Правки» до нуля дефектов — и остался третий блок, превью
в корпусе телефона. Его проверяет `scripts/audit-preview.py` (копия `_audit/rec/checks/audit-preview.py`).

## Что печатает проверка

| Метка | Что значит |
|---|---|
| `COUNT` | экранов в блоке не три |
| `NOCOMP` | на экране нет ни одного класса главного компонента |
| `DUP` | два экрана совпали разметкой |
| `OVERFLOW` | элемент вылез за `.phone__screen` |
| `CLIPPED` | текст срезан (`scrollHeight/Width > client`) |
| `EMPTY` | меньше 6 видимых элементов или занято < 35 % высоты экрана |

Классы главного компонента берутся из его собственного CSS
(`iiko-ds-web/components/<ds_page>/*.css` + `iiko-ds-mobile/.../*.css`), а не из имени страницы:
иначе `NOCOMP` срабатывает на окружение (список, поиск, кнопки есть на любом экране).

## Главная ловушка проверки: обрезающий предок не отменяет layout-бокс

`getBoundingClientRect()` отдаёт геометрию даже у ребёнка, обрезанного контейнером, поэтому
«вылезание» надо отличать от задуманной обрезки:

- `overflow: auto|scroll` у предка внутри экрана → прокрутка, дефекта нет
  (горизонтальные табы и строка чипов переполняются именно так);
- `overflow: hidden` у предка внутри экрана → дефекта нет, **если элемент целиком в его боксе**;
- сам `.phone__screen` в список исключений НЕ входит — вылезание за экран это дефект.

Без первых двух правил проверка давала 41 ложное срабатывание на четырёх страницах; после — 1 настоящий
(он же и был последним).

## Четыре страницы, которые пришлось починить

### `sidenav` — панель 360 px не уживается рядом с контентом в экране 375 px

Экран «панель рядом с контентом» сминал список: элементы уезжали до 633 px при ширине экрана 359.
Мобильный слой ДС задаёт панели 360 px (MD3 navigation drawer 360 dp), а экран телефона — 375 px,
то есть панель занимает почти всю ширину и по решению ДС показывается **поверх** контента
(строка страницы: «over — поверх контента, с затемнением Backdrop»). Итоговая разметка экрана:

```html
<div style="position:relative;flex:1;min-height:0;display:flex;flex-direction:column">
  …шапка и тело экрана…
  <div class="phone__scrim"></div>
  <div style="position:absolute;left:0;top:0;bottom:0;width:360px;max-width:100%;
              overflow:hidden;background:var(--ds-color-brand-neutral-super-dark)">
    <div class="ds-sidenav-view">…</div>
  </div>
</div>
```

Две ошибки по дороге: (а) панель сначала осталась «рядом» — контент сминался;
(б) при пересборке оверлея забыт `background` у абсолютной обёртки — панель получалась высотой
по контенту (тёмная полоса сверху), а не на весь экран. Фон должен быть у самой обёртки, не только
у `.ds-sidenav-view` внутри.

Третий экран (навигация на весь экран, панель 360 внутри `.phone__body` с паддингом 16 → доступно 343)
правился сменой паддинга тела: `<div class="phone__body" style="padding:0">` и радиус снят —
полноэкранная навигация края не скругляет, зато панель встаёт в свои 360 px, как на реальном 375-м экране.

### `chips-input` — строка чипов в ДС не переносится

`.ds-chips-input__content { display:flex; flex-direction:row }` и никакого `flex-wrap`,
а ввод стоял с `width:100%` — три чипа и поле вылезали за экран (правый край 371/383 при 359).
В превью: два чипа вместо трёх и у ввода `flex:1 1 60px; min-width:0`.
Сам факт «чипы не переносятся на новые строки» — находка для ДС (страница при этом утверждает перенос),
библиотеку не править, сказать владельцу списком.

### `textarea` — подсказка под полем срезана внутри экрана

`CLIPPED | ds-textarea__hint | До 500 символов`: высота подсказки объявлена 16 px при строке 19 px,
а каркасный фикс `.panel .ds-textarea__hint{height:auto}` до экранов не доходит. Лечение — в `build.py`,
парные правила для `.phone` (см. ниже).

### `tabs` — ложная тревога, поправлена проверка

Табы переполняются внутри `.ds-tabs` с `overflow-x: auto` — это задуманная прокрутка,
исключение «обрезающий предок внутри экрана» её и сняло.

## Пары `.panel` → `.phone` в `build.py`

Экраны лежат ВНЕ `.panel`, поэтому все каркасные находки для панелей надо повторять для `.phone`.
Добавлено (после сборки строки `CSS`):

```css
.phone .ds-menu-container,
.phone .ds-select-container,
.phone .ds-list-container { min-height: 0 }
.phone .ds-textarea__hint { height: auto }
```

Первое снимает замороженные высоты контейнеров автогена (418 / 406 / 257 px — внутри экрана получалось
пустое поле под списком), второе возвращает подсказке полную строку. В файле уже был парный приём для
плашек автогена (`_plates`: строка `.panel .ds-...__support-text` дублируется с заменой `.panel ` на `.phone `)
— новые правки встают рядом и по тому же принципу.

## Подпись экрана — часть разметки

Перестроив экран, обязательно править `.phone__caption`: после переделки в оверлей подпись осталась
от старой вёрстки («Панель рядом с контентом: разделы слева, экран смены справа») и врала про содержимое.
Проверка этого не ловит — только глазами или чтением подписей вместе с разметкой.

## Проверка контента платформ машиной

После разлива по 38 страницам текстовый блок проверяется не глазами, а счётом: по всем
`platform_notes_ru` + `logic_ru` считаются повторы формулировок (`Counter`), проверяется наличие
источника в скобках у каждого пункта и размер колонок (3–6 пунктов). Результат того прогона:
0 повторов, 0 пунктов без источника, 38 страниц с двумя колонками + «Логика». Ноль повторов — признак,
что тексты написаны по своим выгрузкам `_audit/platform/<slug>.json`, а не по шаблону.

## Порядок отчёта владельцу

Он смотрит страницы раньше, чем приходит отчёт («Не вижу в колонке Правки чтобы можно было изменить
какие-либо значения!») — и «поля нет» одинаково означает и «эта страница из списка 9», и «вкладка
открыта до слияния». Поэтому после массовой правки: пересобрать, снять скрин изменённой страницы
и посмотреть vision-ом, дать полный URL текстом и напомнить один `Ctrl+F5`.
