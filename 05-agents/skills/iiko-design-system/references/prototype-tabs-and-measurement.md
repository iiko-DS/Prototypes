# Вкладки и подварианты в страницах-прототипах КДС

Класс задач: страница-набросок в `iiko-ds-prototypes/KDS/*.html` (однофайловый HTML:
разметка + `<style>` + один `<script>`), где надо показать несколько вариантов индикации
на одном состоянии и дать владельцу понажимать. Проверено 16.09 на `KDS/multi-shop.html`.
Доказательный контур (проба `<pre id="probe">`, `--dump-dom`, скриншоты, сверка стилей)
описан в `references/prototype-copy-fidelity.md` — здесь только то, что про вкладки и состояния.

## Каркас вкладок вариантов

- Полоса: `<div class="tabs"><button class="tab is-on" data-vtab="1">…</button>…</div>`.
  CSS: `.tabs{display:flex;gap:4px;flex-wrap:wrap;border-bottom:1px solid #d8dade;margin:0 0 10px}`,
  `.tab{display:inline-flex;align-items:center;gap:8px;padding:10px 16px;border-radius:12px 12px 0 0;border:0;background:transparent}`,
  `.tab.is-on{background:#121212;color:#fff}`.
- Содержимое варианта — `<section class="vpanel" data-vpanel="1">…</section>` плюс
  `.vpanel{display:none} .vpanel.is-on{display:block}`.
- Управление, общее для всех вкладок («Вид экрана: По заказам / По блюдам», «Сброс»),
  оставлять НАД полосой вкладок, а не внутри вариантов.
- Состояние (`pressed{}`, `uiMode`) держать глобальным: переключение вкладки состояние НЕ сбрасывает —
  именно поэтому вкладки и просили («все варианты на одном состоянии, видно разницу»).
- Переключение: `markTabs('#pageTabs [data-vtab]', btn)` → показать нужную `.vpanel` → `paint()`
  → пересчёт размеров (`scrSyncKnob()`).
- Вкладки прячут текст: примечания («как это читается», «что проверить на месте») после разбивки
  должны разъехаться по своим вкладкам, а не остаться одним общим блоком.

### Ловушка: скрытая вкладка = нулевые размеры

Внутри `display:none` `offsetWidth`/`clientWidth` равны 0 → авто-масштаб и полоса прокрутки
дают `NaN` и в стиль уезжает `NaNpx`. Лечится двумя вещами:

1. защита внутри функций: `if(!device.offsetWidth || !H || !stage.clientWidth) return;`
   и `if(!scrollEl.scrollWidth || !scrollEl.clientWidth) return;`
2. принудительный пересчёт при показе вкладки: `paint(); scrSyncKnob();`

Контроль замером после переключения на вкладку экрана: масштаб `1`, высота сцены `H*scale+32`,
холст ленты `2648px`, переполнение страницы `0 px`. Ещё следствие: клик по элементу внутри
скрытой вкладки молча ничего не делает — в пробе сначала переключить вкладку/таб.

## Переключатель отображения ВНУТРИ скопированного экрана

Владелец просит «в самом экране менять варианты табами». Рабочий приём: экран рисует строки
ТЕМ ЖЕ отрисовщиком, что панели цехов (`pbtnHtml`, `pbtnPlainHtml`, `stepsHtml`, `countHtml`),
меняя только классы скелета строки на классы копии (`kdsx-row` / `kdsx-act`) — тогда формы
совпадают один в один, а не «примерно похоже».

- Строка по ветке варианта: v1 — подпись `ms-head` + `countHtml` (плашка «0/3») и `stepsHtml`
  внутри кнопки; v2 — `pbtnHtml` в `.kdsx-actcell`; v3 — `pbtnPlainHtml`.
- Под компоненты вариантов нужны мелкие правила в семействе копии: `.kdsx-act{position:relative}`
  (иначе абсолютный `.step-bar` уедет к другому предку), `.kdsx-act--idle`, `.kdsx-act--ready`,
  `.kdsx-row--wait`, `.kdsx-row--done`.
- Две полосы табов внутри экрана подписывать словами («Отображение блюда в карточке заказа:»,
  «Терминал (чей это экран):») — одинаковые полосы без подписей читаются как одна.

## Подварианты («3.1 только числа» / «3.2 числа и стрелка»)

- Форму задаёт ОДНА глобальная переменная (`v3Arrow`), а не свойство данных блюда: свойство вида
  `arrow:'above'` у блюда делает эксперимент частным случаем одного блюда и мешает — владелец
  попросил вынести это в подвариант (свойство из данных убрано).
- Обе полосы (подтаб на вкладке и таб в экране) пишут одну переменную и синхронизируют отметки
  (`syncV3Tabs()` / `syncScrVarTabs()`), тогда «выбрал 3.2 в экране → подтаб на странице тоже 3.2».
- Размеры держать в одном месте: числа `20 px` в кнопке `56 px`, крупный показ `34 px`;
  иконка стрелки в композиции «над числами» — того же размера, что числа.

## Состояния одной кнопки блюда (единый словарь, чтобы правки не расходились)

- «нажали не все, моё не считается» — числа серым/синим на штатной подложке;
- «мой сброс засчитан, ждём остальных» — числа зелёные, кнопка прозрачная в пунктире, повторно
  не нажимается (это и есть вид «нажимать нечего», его убирать нельзя);
- «готово» — ШТАТНАЯ кнопка: серая подложка 56 × 56 со зелёной галочкой (`pbtn--ready` /
  `kds-act--ready` / `kdsx-act--ready`), без пунктира. Владелец отдельно это поправлял:
  готовая позиция выглядит «как и раньше», то есть как `.kds-act--positive` в `kds-screen.html`
  (серый `#424242` + галочка `#14b456`).
- Серый кант `box-shadow: inset 0 0 0 1px #3a3a3a` вокруг СТРОКИ в состоянии «ждём» владелец
  попросил убрать — читается как «рамка вокруг блюда». Правило лежало в трёх местах
  (`.kds-row--wait`, `.dish--wait`, `.kdsx-row--wait`), убирать во всех сразу.
- **«Готово» — дефолтный вид блюда; единственная зелёная деталь — галочка в кнопке.** Финальная
  формулировка владельца: «никаких раскрасок зелёных, обводок и прочее. Дефолтный вид блюда,
  кнопки и зелёной галочки». Поэтому у «готово» убраны 16.09 не только серые, но и ЗЕЛЁНЫЕ
  канты, и всё остальное украшение состояния: канты строк/карточек (`.kds-row--done`,
  `.dish--done`, `.kdsx-row--done` → только `cursor:default`), зелёный периметр кнопки
  варианта 2 (правило `.pbtn--done` с `ringSvg(100)` удалено целиком), зелёная заливка плашки
  варианта 1 (`ms-count--done` удалён, галочка внутри плашки тоже), серо-пунктирная галочка
  варианта 1 (`kds-act act-idle` + check → `kds-act--ready`). Эталон замера после правки:
  кант `none`, фон кнопки `rgb(66,66,66)`, рамка `none`, галочка `rgb(20,180,86)`, кольца нет.
  НЕ трогать при этом: статус заказа (`kds-status--positive`, зелёная кнопка «Приготовлен» —
  штатный вид КДС, такой же в скопированных карточках) и состояние «мой сброс засчитан»
  (там пунктир остаётся — это вид «нажимать нечего»).
- Приглушённое название (`--kds-text-2`) в состоянии «ждём» — на усмотрение владельца: сам убрал
  только кант, про приглушение спросил.
- **Вариант 2: стрелка и числа.** Стрелка показывается только пока не нажал НИ ОДИН цех, и стоит
  НАД числами (владелец: «поменяй цифры и стрелку местами», «икона 20, шрифт тоже 20»); как только
  нажатия пошли, в кнопке остаются одни числа и периметр. Иконка и числа — `20 px` (было 26 и 16),
  в крупном показе `34`; числа без пробелов вокруг слэша («1/3»), как в варианте 3 — пробелы убраны
  во всех вариантах, поэтому у `numsHtml(d, me, arrow)` параметра `spaced` больше нет.
- **Табы экрана по умолчанию — первые в каждой полосе.** Владелец: «по умолчанию всегда активные
  первые табы сразу»: `screenShop='cold'`, `screenVariant=1`, и отметки `is-on` в разметке должны
  совпадать со значениями в скрипте — иначе до первого клика подсвечен чужой таб.

### Проба вернула пустое `<pre>`? Это ошибка в пробе, а не в странице

Дважды за сессию проба печатала пустоту, и оба раза виновата была сама проба:

- исключение внутри обработчика (например `document.querySelector('.pbtn__num')` в состоянии
  «готово» возвращает `null`, дальше `.textContent` бросает) — оборачивать тело пробы в
  `try{…}catch(e){ L('ОШИБКА', e.message); }`, иначе ошибки не видно вовсе;
- запись результата живёт только в `setTimeout(…, 400)` — если до неё не дошло, `<pre>` пустой;
- вытаскивать результат строго по `<pre id="probe">(.*?)</pre>` (маркер внутри исходника
  скрипта иначе перехватывает регексп).

Заодно: селекторы строк искать ПО БЛЮДУ (`[].filter(... , r => r.textContent.includes('Тёплый салат'))`),
а не «первый `.kds-row`» — в панели цеха первая строка обычно другое блюдо, и замер уезжает не туда.

## Правка больших однофайловых прототипов

- Сначала план: грепнуть `<h1|<h2|<h3|<div class="notes"|data-…`, получить границы блоков.
- Правки — точные строковые замены с `assert s.count(old)==1` (Python в `execute_code`):
  удаление разделов, вставки и переименования не «съезжают». Все замены копить в памяти и писать
  файл ОДИН раз в конце: упавший ассерт тогда оставляет файл на диске прежним (проверено — после
  `AssertionError` в середине скрипта файл не изменился).
- Искать якорь по подстроке опасно: строка вида `+ ringSvg(pct)+numsHtml(d,me,true)+'</button>';`
  встречается и с другим отступом в соседней ветке, `count` полулея 2 — брать более длинный
  контекст (или осознанно `cnt=2`), иначе замена задевает соседний блок.
- После правок: `node --check` на извлечённом последнем `<script>`; баланс `<div>`/`</div>`;
  счётчики по удалённым префиксам (`panels4`, `ms5-band`, …) = 0; переполнение страницы `0 px`.
- `iiko-ds-prototypes/` — gitignored, отката через git нет: перед крупной переделкой держать
  точный список правок, старое без прямой просьбы не удалять.
- Обновлять и шапку-комментарий файла, и `iiko-ds-prototypes/README.md`: владелец читает README
  как реестр страниц.
