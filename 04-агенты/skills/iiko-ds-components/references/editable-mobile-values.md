# Колонка «Правка» — редактируемые мобильные размеры на странице рекомендаций

Задача владельца (12.09.2026): 4-я колонка после «Mobile» в блоке «Что меняется на мобиле», поля с текущими
мобильными значениями; ввёл 40 вместо 44 — кнопка в мобильной панели на этой же странице становится 40.
«И так по всем значениям в таблице». Уточнения, которые он дал по ходу и которые менять нельзя:

- **правим только размеры** — строки про цвет, поведение, показ, токены остаются текстом без полей;
- **«те же» в размерной строке недопустимо** — значение существует (оно равно десктопному), его надо написать числом
  («Я не знаю зачем ты писал теже»);
- **одно поле на каждое число** («Вариант 1»): `12 / 16` → два поля, `40 × 40` → два поля;
- **колонка Mobile не правится** — это рекомендация платформ («Значения в колонке мобайл не правятся. Это
  рекомендованные значения по материал… Ты опять делаешь что-то своё»); колонка «Правка» — отдельная копия чисел;
- **следствия правки должны быть видны** («Нахера это прятать куда-то под капот и вводить в заблуждение»).

## Схема данных (итоговая)

Строка `changes[]` получает необязательное поле `edit` — массив связок, по одной на число в значении Mobile:

```json
{
  "what": "Высота",
  "desktop": "36 px",
  "mobile": "44 px",
  "edit": [
    {"id": "height", "v": 44, "sel": ".ds-btn", "css": "height:@px",
     "sync": {"field": "pad-v", "a": 0.5, "b": -10}}
  ]
}
```

- `id` — имя поля в пределах страницы, по нему ищется цель связки;
- `v` — стартовое значение поля (= мобильное значение страницы);
- `sel` — селектор **внутри мобильной панели** (правило всегда получает префикс `[data-mode="mobile"]`);
- `css` — объявления, `@` заменяется введённым числом;
- `sync` — необязательная линейная связка `t = a·v + b` на другое поле страницы.

## Генератор (`_audit/rec/build.py`)

`changes_table(d)`:

- 4-я колонка — `<td class="edit">` с полями
  `<input class="edit__input" type="number" step="1" value="44" data-id="height" data-sel=".ds-btn" data-css="…"
  data-sync-field="pad-v" data-sync-a="0.5" data-sync-b="-10" aria-label="Высота">`;
- **колонка Mobile остаётся текстом из данных**: ни генератор, ни скрипт её не трогают. Первая версия помечала числа
  в тексте `<span class="v" data-vk="id">` и заменяла их при вводе — эта часть удалена вместе с `_mark_values()`
  (владелец: «Значения в колонке мобайл не правятся»);
- порядок в шаблоне `page()`: `<style id="live"></style>` — **последним в `<head>`**, после `rec.css` и остальных
  ссылок (при равной специфичности решает порядок), скрипт — в конце `<body>`;
- каркасный CSS: `td.edit{white-space:nowrap;width:1%}`, `.edit__input{width:64px;box-sizing:border-box;…}`.

## Скрипт страницы (итоговый)

```js
(function () {
  var live = document.getElementById('live');
  var fields = [].slice.call(document.querySelectorAll('.edit__input'));
  if (!live || !fields.length) return;
  var byId = {};
  fields.forEach(function (f) { if (f.getAttribute('data-id')) byId[f.getAttribute('data-id')] = f; });
  function rebuild() {
    var rules = [];
    fields.forEach(function (f) {
      if (!f.__touched) return;                 /* пока поле не тронуто — правило не пишем */
      var v = f.value === '' ? f.getAttribute('value') : f.value;
      rules.push('[data-mode="mobile"] ' + f.getAttribute('data-sel') +
                 '{' + f.getAttribute('data-css').split('@').join(v) + '}');
    });
    live.textContent = rules.join(String.fromCharCode(10));   /* НЕ '\n' — см. ловушку ниже */
  }
  function syncFields(f) {                      /* следствие правки — в самом поле, а не под капотом */
    var target = f.getAttribute('data-sync-field');
    if (!target || !byId[target]) return;
    var a = parseFloat(f.getAttribute('data-sync-a'));
    var b = parseFloat(f.getAttribute('data-sync-b'));
    var v = parseFloat(f.value);
    if (isNaN(a) || isNaN(v)) return;
    var t = byId[target];
    t.value = Math.round((a * v + b) * 100) / 100;
    t.__touched = true;
  }
  fields.forEach(function (f) {
    f.addEventListener('input', function () {
      f.__touched = true;
      syncFields(f);
      rebuild();
    });
  });
})();
```

Почему так, а не инлайн-стилями: правило в таблице стилей работает и для **псевдоэлементов** (тач-слой
`.ds-btn::after{min-width/min-height}` правится так же, как высота), и `[data-mode="mobile"] <sel>` (0,2,0) перебивает
мобильный файл слоя `[data-mode="mobile"] .ds-btn--m` по порядку (наш `<style>` идёт последним).

**Ловушка:** `page()` — Python-`%`-шаблон, `'\n'` внутри JS превращается в реальный перевод строки → `SyntaxError:
Invalid or unexpected token`, страница молча ничего не правит (`#live` пустой, размеры не меняются). Писать
`String.fromCharCode(10)`. Диагноз: вытащить `<script>` из сгенерированной страницы и прогнать `node --check`
(покажут строку и колонку) либо в пробнике вызвать `new Function(scriptText)()` и прочитать исключение.
Готовый прогон по всем страницам — `scripts/check-page-js.py`.

## Связки «строка → свойство» для Button (образец)

| Строка | Поле | `id` | `sel` | `css` |
|---|---|---|---|---|
| Высота | 44 | `height` | `.ds-btn` | `height:@px` + `sync` на `pad-v` (0.5 / −10) |
| Паддинги верт. | 12 | `pad-v` | `.ds-btn` | `padding-top:@px; padding-bottom:@px` + `sync` на `height` (2 / 20) |
| Паддинги гор. | 16 | `pad-h` | `.ds-btn` | `padding-left:@px; padding-right:@px` |
| Тач-зона нажатия | 48 | `touch` | `.ds-btn::after` | `min-width:@px; min-height:@px` |
| Кегль текста | 16 | `font` | `.ds-btn__label` | `font-size:@px` |
| Иконка | 20 | `icon` | `.ds-btn__icon` | `font-size:@px` |

Почему высота и паддинги связаны: у Button высота = паддинги + строка подписи (20 px у M/S, 16 у XS). Но связь
обязана быть **видимой**: `height` пишет только высоту, паддинги приезжают в своё поле (40 → 10), а не подменяются
незаметным `calc` внутри правила — попытка спрятать это уже получила «вводить в заблуждение».

## Проверка

Синхронный iframe-пробник (`_audit/rec/checks/_probe-edit*.html`): iframe на страницу → в `onload` выставить
`input.value`, `dispatchEvent(new Event('input'))`, затем замерить `getBoundingClientRect()` в обеих панелях,
прочитать поле-цель и `#live`. Вывод в `<pre id="out">` попадает в `--dump-dom` (родительский `load` наступает после
скриптов внутреннего документа).

Замер образца (`button.html`): до — mobile 44, desktop 36; ввод 40 → mobile **40**, поле «Паддинги» **10**,
колонка Mobile по-прежнему «44 px», desktop **36**. Обратный ход: паддинг 8 → высота в поле **36**, кнопка 36.

## Границы

Это правка **страниц рекомендаций** (`_audit/rec/data/*.json` + `build.py`), а не библиотеки: `iiko-ds-web`
не трогается, введённые значения живут до перезагрузки страницы. Запись значения в файлы (то есть превращение правки
в рекомендацию) — только по отдельному слову владельца.
