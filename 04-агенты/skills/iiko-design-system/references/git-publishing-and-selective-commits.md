# Публикация в GitHub: часть файлов уезжает, часть нет

Класс работы (15.09.2026): «У меня много файлов здесь локально в папке гит. Я хочу часть опубликовывать,
часть нет. И я думал что есть такая функция опубликовать или нет. Я ошибся?» → следом «Как это сделать
точно?». Владелец проверяет по числам и командам, а не по пересказу, поэтому ответ строится так:
сначала модель («публикуется коммит, а не файл»), потом таблица «что у нас уже опубликовано»,
потом точные команды, и в конце — репетиция на живом репозитории с возвратом состояния.

## 1. Модель, которую надо объяснить

- У файла в git нет и не бывает флага «опубликован». Публикуется **коммит**: что отметили (`git add`
  или галочкой) и отправили (`git push`). Всё остальное остаётся локальным.
- Значит «часть публикую, часть нет» = выборочное добавление в коммит + `.gitignore` на то, что не
  публикуется никогда.
- Галочки на самом деле есть, но в момент коммита: VS Code (Ctrl+Shift+G → «+» у файла → «Staged
  Changes»), GitHub Desktop (файл = галочка). Кнопки «Stage All Changes» / «Commit All» — то же
  «отметить всё».
- Отдельно «опубликовать один файл мимо репозитория» умеет только **gist**; **Pages** — публикация
  показа из выбранной папки/ветки (не по файлу); видимость репозитория — Settings → Change visibility
  (на весь репозиторий сразу).

Проверка состояния без токена и без печати учётных данных:

```bash
git remote -v
git log --oneline -1 && git ls-remote --heads origin | head -3      # прошло = учётные данные уже есть
GIT_TERMINAL_PROMPT=0 git push --dry-run origin main               # права есть; ничего не отправляет
curl -s -o /dev/null -w "%{http_code}\n" https://github.com/<owner>/<repo>            # 404 => приватный
curl -s -o /dev/null -w "%{http_code}\n" https://<owner>.github.io/<repo>/<путь>       # что уже опубликовано
git ls-tree -r --name-only origin/main | grep <имя>                # «файл уже там?» (для приватного raw не отдаст)
```

## 3. Выборочный коммит — точный порядок

```bash
cd C:/Users/asukharev/GitHub/DS/<репозиторий>
git status --short                                 # ?? новое (не уедет) / A отмечено (уедет) / M / D
git add <файл> [<файл>…]                           # только нужные, через пробел
git diff --cached --name-only                      # ЕДИНСТВЕННЫЙ источник правды: это и уедет
git commit -m "<сообщение>"
git push origin main
git ls-tree -r --name-only origin/main | grep <файл>   # проверка, что уехало
```

- «Отметить всё» — это `git add .`, `git add -A`, `git commit -a`. На `iiko-ds-prototypes` сухой
  прогон `git add --dry-run -A` показал **98 файлов**: снёс бы с GitHub шесть `kds-*.html` и залил
  `KDS/`, `_crops/`, все `_figma-*.png`. Число показывать владельцу до правки — он решает по числам.
- Отмена: отметили лишнее → `git restore --staged <файл>` (сам файл не тронут); закоммитили, но не
  пушили → `git reset --soft HEAD~1`, заново отметить, закоммитить; уже улетело → `git rm --cached <файл>`
  + коммит + push (локально файл остаётся).
- Удаление файла у себя **не** удаляет его из GitHub, пока не закоммитите `D` — шесть `kds-*.html`
  именно так и остались лежать в репозитории при удалённых локальных копиях.
- `.gitignore` в `iiko-ds-prototypes` нет вовсе; кандидаты на исключение — `_crops/`, `_figma-*.png`,
  `KDS/` (создание — отдельное решение владельца).

## 4. Репетиция на живом репозитории (владельцу нравится)

Отметить один файл, показать `git diff --cached --name-only` («ровно одна строка — вот что уедет») и
`git status --short` (`A  <файл>`), затем `git restore --staged <файл>`; списки `git status --short`
до и после сверить через `diff -q` и сказать прямо: состояние ровно как было, ни один файл не изменён.
Так делалось с `callcenter-noncash-payment.html`: 1 файл в индексе → 0 после отката, дифф списков пустой.
Пустой индекс — норма: без явного «делай» ничего не коммитится и не пушится.

## 5. Что ломается при публикации прототипа «как есть»

- Страница ссылается относительно: 7 ссылок `../iiko-ds-web/*` (папка в репозиторий не входит — в
  `.gitignore` корня) и 5 ссылок на `app-header/`, `app-sidenav/` (23 файла, тоже не в репозитории).
  На GitHub такой файл откроется как исходник, а не как страница.
- Публикация «как у `kds-*`» = заменить ссылки на `https://anders7rusk.github.io/iiko-ds-web/...`
  (font/tokens/styles/components/index.css/radio*.css там отдают 200), догрузить обвязку
  `app-header` + `app-sidenav` в репозиторий и включить Pages. **Pages на приватном репозитории
  включается только на платном плане** — обещать «живую страницу» после push нельзя.
- Опубликованная копия ДС отстаёт от локальной: `fixes.css` по Pages-адресу **404** (локально есть,
  в репозитории не закоммичен), а `tokens.css` отличается (сверять `curl`-выгрузку через `diff`).
  Значит страница соберётся на другой версии ДС — говорить это до публикации, а не после.
- ⛔ `iiko-ds-web` не править и не пушить без прямого слова владельца; публичная папка = изменения ДС
  станут видны всем.

## 6. Капканы

- Вопрос «как опубликовать» — это объяснение, а не разрешение: не коммитить, не пушить, не включать
  Pages по своей инициативе, пока не сказано «делай».
- Не называть приватный репозиторий опубликованным: проверять анонимный статус страницы, а не свою
  способность сделать `ls-remote` (учётные данные в кэше дают успех и на приватном).
- Предупреждение `LF will be replaced by CRLF` при `git add` в этих репозиториях — про переводы строк,
  содержимое страницы не меняется; так и сказать, чтобы владелец не принял его за порчу файла.
