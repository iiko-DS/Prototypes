# Разборы и аналитика

Сюда складываем всё, что помогает понять систему и принимать решения: разборы компонентов, замеры, сравнения, выводы из ревью, исследования поведения.

## Правила

- **Один разбор — один файл.** Имя: `YYYY-MM-DD-тема.md`, например `2026-10-02-кнопки-в-строках.md`. Дата в начале — чтобы список сортировался сам.
- **Начинать с вывода, а не с процесса.** Первые два абзаца должны отвечать на вопрос «что мы решили и почему», остальное — доказательства: замеры, цифры, таблицы.
- **Цифры, а не прилагательные.** «Отступ 8 вместо 12» проверяемо, «выглядит тесно» — нет.
- **Скриншоты не храним.** Проверочные снимки живут до конца задачи и удаляются: то, что нужно доказать, доказывается замером, а не картинкой. Если разбору нужна картинка — она должна быть схемой или макетом, а не снимком экрана.
- **PDF и тяжёлые выгрузки** — рядом с разбором, тем же префиксом по дате.

## Где уже лежат исторические разборы

Разборы по KDS (экраны кухни, карточки заказов, сценарии) лежат в репозитории прототипов: `iiko-ds-prototypes/KDS/`, файлы с префиксом `_kds-*`. Переносить их сюда не обязательно — ссылку из разбора достаточно. Новые разборы по ДС в целом логичнее складывать здесь.
