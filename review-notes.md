# iiko DS — журнал косяков ДС (компоненты / токены / CSS)

Назначение: проблемы САМОЙ дизайн-системы — что в компонентах/токенах/стилях отрисовано или
работает неправильно и что нужно доправить. Отличия от макетов-доноров здесь НЕ пишем: донор
может быть любым (Figma, Balsamiq, текстовое описание) — прототип всегда собирается строго
по ДС. Находки копятся из подсказок на страницах (ссылка «Подсказки ДС» / `?hints=1`).

Учитываем: Фигма — статика (скриптов и интерактива там нет; многое в макете просто не видно).
Поведение (ховеры, фокус, всплытие Label, фильтрация) существует только в коде; в Фигме можно
показать лишь статичные варианты состояний. Поэтому пишем так: механику чиним в CSS/JS ДС,
а в Фигме — досоздаём варианты состояний, если их нет; «интерактив в Фигме» не требуем.

Как отдавать: файл самодостаточен (можно целиком — например, Гермесу). Нумерация сквозная;
формат пункта: что не так → что доправить → где (Фигма / токены / CSS).
Контекст: `iiko-ds-web/components/<Имя>_DS/*.css`, `tokens.css`, `iiko-ds-mobile/`, `iiko-ds-spec.md`.

Дата старта: 2026-09-12 (пересобран под правило «только косяки ДС»).

## Table (Table_DS)

1. **Шапка: рамка и фон дублируются** — и у ячейки (`table-header-cell.css`), и у полосы
   (`table-header-row.css`); при сборке швы двойные, фон дважды. Скругление полосы (radius 8)
   перекрыто прямоугольными ячейками (нет clip). → ДС: один владелец рамки/фона, полосе — clip.
2. **Ховер-конфликт:** строка красит фон (#F5F5F5), ячейка под курсором рисует свою рамку
   (#9E9E9E) — двойной отклик. → развести состояния (`table-content-row.css` / `table-content-cell.css`).
3. **Ячейка-ссылка (State=Link):** состояние Link у Table content cell в компоненте есть
   (8 вариантов), в CSS не реализовано — ни класса-модификатора, ни токена цвета ссылки;
   значения-ссылки (имя поставщика, дата «Прайс-листа») выводятся обычным текстом.
   В прототипах до правки ДС — временный стиль (решение заказчика 2026-09-12):
   Accent + подчёркивание по ховеру.
   → `table-content-cell.css`: модификатор `--link` + токен цвета (в ДС ссылки уже есть:
   Text UI/Link, List item/Link → Accent).
4. **Полосы строк свёрстаны колонкой** (`ds-table-*-row { flex-direction: column }`) — строку
   из ячеек не собрать. → починить развёртку (`table-header-row.css` / `table-content-row.css`).

## Hint / Tooltip (экран 2)

16. **Автоген: `background` = цвет текста у 23 текстовых классов** (перечень — в `rec.css`
    страницы рекомендаций ДС, раздел «Артефакт автогена библиотеки»); пример — у
    `.ds-hint-header__title` фон задан токеном цвета текста, из-за чего заголовок подсказки
    рисуется сплошной плашкой. Рекомендации ДС гасят это на странице (`.panel … {background:none}`),
    библиотека не правится; прототипы делают так же. → почистить `background` у текстовых классов
    (в первую очередь `hint-header.css`). (CSS)
17. **Hint container: плашка рисуется с ошибками** — (а) фон не задан ни у контейнера, ни у `__label`:
    текст в `__label` — белый на прозрачном (тёмную плашку дают только вложенные блоки
    header / content / footer / arrow), Single-подсказка собирается через `ds-hint-content--single-content`;
    (б) у фоновых блоков нет `border-radius` — плашка выходит с квадратными углами, скругление
    контейнера (8 px) к фону не применяется (нужен радиус блокам либо `overflow:clip` контейнеру).
    → задать фон контейнеру/лейблу; скругление — фоновым блокам. (CSS)

## Button (размеры)

18. **Несколько размеров — нет правила выбора:** у Button (и родственных — Button icon и др.)
    три размера: XS 24 / S 28 / M 36; где какой применять — не задано. В статике размер
    не читается: S и M отличаются только внутренними паддингами и зазором иконка–текст
    (4 vs 8 px), поэтому в вёрстке легко собрать кнопку не тем размером. → таблица применения
    размеров (где S, где M); в применениях/спеках указывать размер. (Фигма + CSS)

## Table (экран 3 — правка прайс-листа, 7436)

19. **Строка с ошибкой — состояния нет:** в макете ошибочные строки подсвечены фоном
    (переменная Overlay/Error → палитра Negative/50), под них завязан фильтр «Показать только
    товары с ошибками». В ДС у строки только Default / Hover / Disable. → вариант Error у строки
    + CSS-токен фона (`table-content-row.css`).
20. **Редактируемые ячейки (`input-cell` / `select-cell` / `input-number`) — hover бьёт по ячейке:**
    `:hover` вешает рамку #9E9E9E на САМУ ячейку: в покое рамки нет → при наведении +1 px и
    раскладка «скачет», а рамка дублирует рамку кадра поля внутри. → рамку состояния рисовать
    кадру поля (`__frame`), а не ячейке. (CSS)
21. **Input number: свойство Close icon есть, CSS — нет:** в Фигме у компонента есть булев
    Close icon (вариант с «×» для очистки), класса/варианта в CSS нет — очистку собираем слотом
    `__icon`. → вариант Close icon + CSS (как у Input). (Фигма + CSS)
22. **Кадры полей в ячейках:** у `input-cell__frame` / `select-cell__frame` не заданы внутренние
    паддинги (текст липнет к рамке); у `input-number__frame` нет `box-sizing: border-box` —
    при `height: 48 px` и паддингах 12 поле фактически ~74 px; та же болезнь у
    `input-datepicker__frame` (тот же корень, что на странице рекомендаций).
    → паддинги + box-sizing в CSS. (CSS)
23. **Input number — детали не выровнены по центру:** у `.ds-input-number` не задан `align-items` —
    когда ячейка растягивается по высоте строки (редактируемая таблица), «×» прилипает к верху,
    «%»/«₽» — к низу: детали разъезжаются по вертикали. → `align-items: center` в CSS. (CSS)
24. **Input number: размеры S/XS не описаны в коде** — в Фигме у компонента есть Size S (36 Hug: поле +
    кнопки шага), локально нет: у токенов `Input number/Input` и `Input number/Control` нет размерных
    осей (один набор: паддинги 8, радиус 8, текст 14, гэп 4/2), в `input-number.css` модификаторы
    `--s/--xs` меняют только ширину, у `input-number-but-icon.css` размерных модификаторов нет вовсе
    (min-height 56, кнопки — Button icon M). Плюс расхождение токены↔CSS: по токенам поле 8/8/14,
    по CSS — 12/12/16 (и кадр 48). → дозавести токены размеров и модификаторы (кнопки — по токенам
    Button icon S/XS). (Фигма + токены + CSS)
25. **Status: подпись не берёт цвет варианта** — у `.ds-status__label` жёстко прописан нейтральный
    цвет (`--ds-color-status-neutral-filled-text-color`): у Warning/Filled подпись рендерится серой
    #616161 вместо #ea7806 (в макете — оранжевая), цвет варианта с корня до подписи не доходит.
    Там же автоген: у `.ds-status__content` `background` задан токеном цвета текста. → не задавать
    цвет подписи (inherit/токен варианта); background `__content` — из Background-токена. (CSS)
26. **Ховеры не обёрнуты в @media (hover: hover)** — все `:hover`-правила слоя (кнопки, поиск, ячейки,
    табы и т.д., ~31 файл) применяются и на тач-устройствах: после тапа состояние «липнет» до
    следующего тапа (sticky hover; пример — бордер `.ds-search:hover` остаётся после нажатия).
    В мобильных версиях ховер-состояний быть не должно. → оборачивать ховер-правила в
    `@media (hover: hover) and (pointer: fine)` (конвертер; правило — `generator-rules.md`, п. 5). (CSS)

## Веб-КЦ: безналичная оплата на контрагента (`callcenter-noncash-payment.html`, доработка 15.09.2026)

34. **Select (Container): жёстко 240 × min-height 406** — подложку списка в ДС нельзя растянуть по месту:
    в модальном окне «Контрагент» (список + поиск + две кнопки) контейнер собирается переопределением
    ширины и высоты в обвязке. → дать контейнеру филл по родителю и высоту по контенту (`min-height` —
    только для превью-карточки). (CSS)
35. **Select item: значение справа не прижимается** — ширина строки 258 px захардкожена, и в CSS нет правила,
    расталкивающего `__element-left` (иконка/текст) и `__element-right` (значение) по краям — в списке

    только обвязкой. → `width: 100%` + `justify-content: space-between` (или `margin-left: auto` правому слоту).

36. **Select item: состояния True/False есть в Фигме, в CSS Selected не реализован** — у `--true` и `--false`

    что у Table content cell / List item. → перенести состояние Selected из Фигмы (токены фона и цвета). (Фигма + CSS)
37. **Служебные слоты красят фон белым** — `.ds-select-item__element-left/__element-right` и `ds-element-select`
    имеют `background: #ffffff`; фон перекрывает ховер (`--false:hover`) и выбранное состояние строки. → фон слотов
    прозрачный (`background: transparent`), цвет — наследованием. (CSS — тот же класс дефекта, что у Table content
    cell, п. 5 журнала)
38. **List (Container): разделитель внутри списка невидим и нет правила «значение справа»** — у
    `.ds-list-container__divider` фон `#ffffff` (на белом контейнере линии нет вовсе), а у строки `__item`

    разделять компонентом Divider и прижимать сумму обвязкой. → divider наследует цвет линии контейнера;
    строке — `space-between`. (CSS)
39. **Radio button: контрол и иконки не попали в агрегатор `components/index.css`** — из `Radio-Button_DS`
    подключён только `radio-button-label.css`; `radio.css` (flex, зазор 8, состояния) и `radio-icons.css`
    (svg-иконки выбран/не выбран) не подключены, поэтому `.ds-radio` из коробки не рисуется: иконки состояний
    нет, подпись липнет к рамке радиокнопки (замер до правки: зазор 0 при 20 px боксе). Страница догружает
    оба файла вручную. → добавить оба файла в агрегатор (тот же корень, что у Checkbox, п. 32). (CSS/сборка)
40. **Текстовой подсказки и состояния загрузки в ДС нет** — «Выберите контрагента» у недоступной кнопки
    приходится собирать элементом поля `ds-input__support` (как у Input), а загрузку списка — иконкой
    `autorenew` с вращением (`@keyframes`), потому что спиннер в ДС есть только в Snackbar (Progress),
    а скелетона строк нет. → компонент подсказки/подписи (Caption) для строки действий + состояние Loading

41. **Иконки-«пунктирной стрелки» в ДС нет (решение: не нужна)** — для блюда, которое готовят несколько
    цехов, кнопка «дальше» не должна обещать переход статуса за одно нажатие. В наборе подходящая иконка
    есть (`line_end_arrow`, теги: arrow, arrowhead, dash), но только в Material Symbols — в классическом
    Material Icons она рисуется словом (замер: глиф 28 px против 560 px текста). В прототипе пробовали её и
    отказались: «обещание перехода» снимается метками шага на самой кнопке, без второго шрифта.
    Тема остаётся открытой на будущее, если понадобятся иконки из Material Symbols. (Шрифты)
