# iiko DS — правила работы в этом воркспейсе

## Главное правило: в прототипах используем ТОЛЬКО компоненты ДС

- Любой блок интерфейса на страницах-прототипах (`iiko-ds-prototypes/**`) собирается из компонентов дизайн-системы:
  готовые классы `ds-*` из `iiko-ds-web/components/*_DS/*.css` (подключён общий `components/index.css`) и токены из `iiko-ds-web/tokens.css`.
- **Макет (Figma) задаёт структуру и тексты. Внешний вид задаёт ДС.** Стили макета НЕ переносим на компоненты
  (капс, цвета, трекинги, радиусы, внутренние паддинги/размеры) — у компонента есть свои токены и состояния.
- Кастомные классы «своей вёрстки» запрещены. Допустимы только:
  1. обвязка раскладки (позиционирование, ширины колонок, гэпы контекста);
  2. правки поверх ДС — только когда у ДС реальный пробел, с комментарием в коде `/* косяк ДС: … */`;
  3. новые компоненты — только если в ДС такого компонента НЕТ, с явной пометкой и записью в подсказки/журнал.
- Настройка компонентов — через их же переменные (`--ds-…`), а не переписыванием стилей.
- Иконки — Material Icons по имени (`<span class="material-icons">search</span>`), семейство Outlined;
  фирменные глифы (например «товар») — точной выгрузкой из макета (инлайн svg с `fill: currentColor`, как в ДС).

## Где что лежит

- Спека компонентов (описания, варианты, состояния, CSS): `iiko-ds-web/iiko-ds-spec.md` — читать ПЕРЕД сборкой блока.
- Классы компонентов: `iiko-ds-web/components/<Name>_DS/*.css`; общий индекс: `iiko-ds-web/components/index.css`.
- Токены: `iiko-ds-web/tokens.css`; правки поверх генерации: `iiko-ds-web/fixes.css` (подключён последним).
- Прототипы: `iiko-ds-prototypes/*.html` (каркас страниц описан в `iiko-ds-prototypes/README.md`).
- Журнал косяков ДС для передачи агентам: `iiko-ds-prototypes/review-notes.md`.

## Проверка перед сдачей блока

1. В разметке — классы `ds-*` и слоты компонентов (BEM-структура из спеки), а не самодельные.
2. Внешний вид сверен со спекой (состояния Default/Hover/Press/Selected/Disable — из ДС).
3. Каждая правка поверх компонента — с комментарием, почему (какой пробел ДС).
4. Если найден пробел ДС — добавить запись в `review-notes.md` и/или подсказки на странице.

## Чек-лист из замечаний заказчика (дополнять при каждом новом замечании)

Проверять ПЕРЕД сдачей любого нового блока — на этих вещах уже ловили:

- **2+ однотипных элементов → групповой компонент ДС** (спека, шаг 3а): 2+ кнопки → `Button group`
  (`ds-btn-group ds-btn-group--horizontal`; в футерах — ещё `--margins`); зазор — только токен
  `--ds-button-group-gap`, свой gap/margin кнопкам не задавать. Порядок: второстепенные слева,
  главная последняя справа; на мобильном — тоже в строку, если кнопки умещаются (решение заказчика
  2026-09-13: «умещаются в строчку — ставим в строчку»); в столбик — только когда не влезают
  (тогда главная кнопка сверху).
- **Композиты — только через базовый контейнер + его слоты** (пример: подсказка — `ds-hint-container--default`
  + `ds-hint-content--single-content`); субкомпоненты (header/footer) вместо контейнера не подставлять.
- **Таблицы: паддинг ячейки 8 — всегда** и живёт на компоненте-ячейке; содержимое (поле/кнопка/слот) — только
  внутрь ячейки; служебные слоты и `element-cell` фон НЕ красят (иначе перекрывают ховер/фон ошибочной строки).
- **Отступы — замером по координатам макета, не на глаз**: `get_metadata` даёт точные x/y/высоты; после сборки
  сверить в браузере через `getBoundingClientRect` (ряды, гэпы, футер) — не «по скриншоту».
- **Новые классы обвязки — только с уникальными именами**: перед вводом проверить grep'ом по странице и ДС,
  что имя не занято (случай `.pp-field`: стили инпутов таблицы раздували обёртки полей панели — гэпы выросли вдвое).
- **Оверлеи/панели**: системные полосы устройства (статус/навбар) не затемнять; оверлей выше шапки приложения;
  закрытие — X / «Отмена» / клик по затемнению (Backdrop из ДС) / Esc.
- **Кромки «экрана»**: полосы устройства — ВЫШЕ оверлеев (z-index 61), оверлеи заходят на 1px под них;
  на мониторе оверлеи/панели повторяют радиус углов экрана (r16, `overflow:hidden`) — квадратный угол
  не должен вылезать на безель; служебный `outline` кадра при системных полосах отключён (ложился светлой
  линией на статусбар). Проверка — пиксельной пробой в настоящем Chrome (`_audit/panel-corners.mjs` + RLE),
  не по скриншотам браузерной панели.
- **Свайп на тач-пресете** (табы, обёртки таблиц): горизонтальная прокрутка = протяжка мышью (touch-mode.js);
  активный таб при входе в тач-режим должен подскроллироваться в видимую зону.
- **Решения заказчика выше макета**: если что-то отменено по указанию (напр. белый индикатор пункта рельса),
  в новых макетах это НЕ возвращать.
- **Прототип выглядит как макет**: никаких видимых панелей демо-состояний/отладочной обвязки — подобное
  делаем только через невидимые URL-параметры.

Новые замечания заказчика — сразу сюда, в этот список (файл подхватывается в каждый чат автоматически).
Детали и уроки по страницам — в рабочей памяти агента; косяки самой ДС — в `review-notes.md`.
