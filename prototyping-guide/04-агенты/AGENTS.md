# Правила работы с дизайн-системой iiko

Файл для ИИ-агентов: читать перед любой работой с компонентами, прототипами и значениями ДС.

## Главное

- **Интерфейс собирается только из компонентов ДС.** Готовые классы `ds-*` из `components-web/components/<Имя>_DS/*.css` (общий индекс — `components/index.css`) и токены `--ds-*` из `components-web/tokens.css`.
- **Макет (Figma) задаёт структуру и тексты. Внешний вид задаёт ДС.** Стили макета на компоненты не переносим: капс, цвета, трекинги, радиусы, внутренние паддинги и размеры — у компонента свои токены и состояния.
- **Самодельные классы запрещены.** Допустимо только: обвязка раскладки (позиционирование, ширины колонок, гэпы контекста); правка поверх ДС — только при реальном пробеле системы и с комментарием в коде `/* косяк ДС: … */`; новый компонент — только если такого в ДС нет, с пометкой.
- **Настройка компонента — через его переменные** (`--ds-…`), а не переписыванием стилей.
- **Иконки** — Material Icons по имени (`<span class="material-icons">search</span>`), семейство Outlined. Фирменные глифы — точной выгрузкой из макета, инлайн svg с `fill: currentColor`.

## Проверка перед сдачей блока

1. В разметке — классы `ds-*` и слоты по спецификации, а не самодельные.
2. Внешний вид сверен со спецификацией; состояния Default / Hover / Press / Selected / Disable — из ДС.
3. Каждая правка поверх компонента — с комментарием, какой пробел ДС она закрывает.
4. **2+ однотипных элемента → групповой компонент ДС.** Две и более кнопки — `ds-btn-group` (`ds-btn-group--horizontal`), зазор только токеном `--ds-button-group-gap`, свой `gap`/`margin` кнопкам не задавать. Порядок: второстепенные слева, главная последняя справа.

## Работа с репозиториями

- `main` — общая база: прямых коммитов в неё нет. Своя ветка (`имя/что-делаю`) → коммит → Pull Request.
- Описания коммитов и PR — по-русски и по делу: что изменилось и почему.
- Не коммитим: собранные страницы (`components-mobile/prototypes/recommendations/` — вывод генератора), проверочные скриншоты и пробы, секреты (`.env`, `.vscode/mcp.json`).
- Страницы компонентов генерируются: правки в HTML затрутся. Правим данные — `_audit/rec/data/<slug>.json` (страница) или `_audit/platform/<slug>.json` (мобильные значения) — и пересобираем.

## Где что лежит

| Что | Где |
|---|---|
| Спецификация ДС (читать перед сборкой блока) | `components-web/iiko-ds-spec.md` |
| Токены | `components-web/tokens.css` |
| Правки поверх генерации библиотеки | `components-web/fixes.css` |
| Компоненты десктопа | `components-web/components/<Имя>_DS/*.css` |
| Мобильный слой | `components-mobile/components/…`, `components-mobile/modes.css` |
| Прототипы экранов | `Prototypes/` |
| Данные страниц компонентов | `_audit/rec/data/<slug>.json` |
| Технические заметки по компоненту | `_audit/rec/data-tech/<slug>.json` |
| Мобильные значения компонента | `_audit/platform/<slug>.json` |
| Сборка страниц | `python start.py` (сборка + сервер), `python doctor.py` (проверка окружения) |

## Подробные знания

Скиллы рядом, в `skills/`:

- `skills/iiko-ds-components/SKILL.md` — компоненты в работе: раскладка и переполнение, состояния кнопок, иконки, мобильный слой, страницы рекомендаций и механизм ревью;
- `skills/iiko-design-system/SKILL.md` — устройство системы: токены, спецификация, правила применения, разбор реальных экранов.
