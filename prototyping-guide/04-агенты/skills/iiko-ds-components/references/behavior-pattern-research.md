# Паттерны поведения: что это, что — нет, как собирать и дописывать

Правила владельца проекта (iiko DS, страницы `_audit/rec`). Собраны из сессий, где он
дважды сказал «это не то» — сначала про правила вместо ситуаций, потом про темы.

## Что такое паттерн поведения (и что им не является)

Паттерн = **конкретная ситуация на телефоне** (экран 375 px). Всегда три пункта,
в этом порядке:

- `Что происходит: …` — что видит и чувствует человек на экране;
- `Что делают системы: …` — что делает **названная** система/продукт, с дословной
  цитатой в кавычках (английский оригинал);
- `Что делать нам: …` — решение для мобильной ДС.

Плюс обязательные поля: `src` («Источники: Система · Раздел (полный https://…)»),
`example_html` (разметка ДС ровно этого случая) и `example_ru` (одна фраза, что показано).

**НЕ паттерн** (владелец: «это рекомендации, а не паттерны поведения», «нашёл дичь»):

- общие правила и рекомендации — «подписывать кнопку действием, а не „OK“»,
  «одно главное действие на экран», «не использовать кнопку для перехода»;
- заметки о происхождении данных — «у платформы такого компонента нет»,
  «числа только из одной реализации», «что писать в таблице, если числа нет»;
- сквозные темы, не привязанные к ситуации: тёмная тема, контраст, локализация и
  растяжение текста, RTL, планшет/поворот/сплит-вид, термины ARIA и live region,
  виртуализация, производительность, «сколько цветов терпимо на экране»;
- «доступность» сама по себе — только как часть ситуации («человек не понимает,
  что делает иконка»), без терминов ARIA/role/live region.

Формулировки-образцы (приняты владельцем): «Третье и четвёртое действие не влезают»,
«Длинная подпись», «Кнопка „Сохранить“ ушла под клавиатуру», «Свайп по строке:
действия спрятаны за жестом, а случайный свайп удаляет», «Системная „Назад“
выбрасывает из мастера», «Ошибка ушла вместе со снекбаром, а пользователь всё ещё ждёт».

## Реальные кейсы и специалисты

Владелец требует не только платформенных документов, но и **кейсов компаний** и
разборов признанных специалистов — каждая строка с адресом и дословной цитатой.

Рабочие маршруты (проверены вытаскиванием текста, не по памяти):

- Apple HIG — только JSON-эндпоинт:
  `https://developer.apple.com/tutorials/data/design/human-interface-guidelines/<page>.json`
  (buttons, alerts, context-menus, lists-and-tables, pickers, layout, gestures, typography).
  HTML-версии страниц отдают 403; `/localization.json` не существует (404).
- Material: `raw.githubusercontent.com/material-components/material-web/main/docs/components/<comp>.md`;
  старые spec-страницы `m1.material.io` (текст есть) и `m2.material.io` (часто пусто,
  JS-рендер); Android-реализация — `material-components-android` в raw.
- Carbon: `raw.githubusercontent.com/carbon-design-system/carbon-website/main/src/pages/components/<comp>/usage.mdx`.
- Ant Design: `raw.githubusercontent.com/ant-design/ant-design/master/components/<comp>/index.en-US.md`.
- GOV.UK: `design-system.service.gov.uk/components/<comp>/` (часть текста отдаёт, остальное — из raw
  репозитория alphagov/govuk-design-system).
- NN/g — `nngroup.com/articles/<slug>/` отдаёт全文: `bottom-sheet`,
  `accidental-overlay-dismissal`, `contextual-swipe`, `touch-target-size`, `cards-component`,
  `mobile-input-checklist`, `date-input`, `input-steppers`, `tooltip-guidelines`,
  `accordions-complex-content`, `ok-cancel-or-cancel-ok`.
- Справки продуктов (Google/Apple/WhatsApp): часть адресов 404, часть JS-рендер —
  проверяй код ответа до того, как ссылаться.
- `curl` — нативный бинарник: пути только `C:/…`; MSYS-путь `/c/…` он не понимает и
  тихо пишет файл нулевой длины.

Цитата обязательна и должна быть подтверждена запросом страницы. Не подтвердил —
`verified: false`, и в паттерн это не идёт. Выдумывать числа и цитаты нельзя.

## Бриф для субагентов: что сработало, а что дало мусор

Первый бриф («собери кейсы и правила по компонентам») дал 375 пунктов, из которых
половина — правила, темы и RTL; владелец забраковал («при чем тут контрастность темы»).
Второй бриф дал 131 годную ситуацию. Разница — в постановке:

- вход — массив `{situation, happens, systems, us, quote, who, url, verified}`;
- в задании прямым текстом: «паттерн = ситуация на телефоне; правила, заметки об
  источниках и темы (тёмная тема, контраст, локализация, планшет, ARIA) — НЕ писать»;
- «сначала прочитай уже написанные `patterns_ru` этого компонента и ищи только НОВЫЕ
  ситуации, не повторяя имеющиеся»;
- 2–4 ситуации на компонент, каждая с подтверждённой цитатой;
- искать кейсы продуктов (Gmail, Apple, WhatsApp, Spotify, YouTube, Walmart,
  B&H Photo, Overcast) и разборы специалистов (авторы NN/g, Baymard, Smashing).

## Дописывать, а не заменять

Правило владельца: «Старое не удаляем, дописываем новое что нашли» — повторено дважды
после того, как я один раз заменил содержимое массовым вливанием.

Git в корне DS уже есть (ветка `main`, `core.autocrlf=false` — чтобы `data/*.json`
хранились байт в байт); вложенные `components-web` и `Prototypes` — отдельные репы
и стоят в `.gitignore` корня. Как доказать, что старое не потеряно:

```bash
cd /c/Users/asukharev/GitHub/iiko-DS/DS && git add -A && git commit -m "снимок перед дописыванием"
# после правки: первые len(old) объектов должны совпасть байт в байт
python - <<'PY'
import json, glob, os, subprocess
for p in sorted(glob.glob('out/patterns/*.json')):
    slug = os.path.basename(p)[:-5]
    new = json.load(open(p, encoding='utf-8'))['patterns_ru']
    old = json.loads(subprocess.run(['git','show','<commit>:_audit/rec/out/patterns/%s.json'%slug],
                                    capture_output=True, text=True,
                                    cwd=r'C:\Users\asukharev\GitHub\iiko-DS\DS').stdout or '{}').get('patterns_ru') or []
    assert new[:len(old)] == old, slug
PY
```

В `checks/check-patch.py` лимит `PAT-COUNT` поднят до 3–24 (было 3–6), иначе дописанные
паттерны не проходят проверку.

## Приёмка дописанного

`python checks/check-new-patterns.py` (запускать из `_audit/rec`) — смотрит только
записи после базового коммита: полный `https://` в источниках, ровно три пункта
с нужными началами, английская цитата, `example_html` + `example_ru`, отсутствие
повторяющихся заголовков. Плюс `python checks/check-patch.py <slug>` по каждому слагу.

## Провал этой сессии — не повторять

Я влил 37 подготовленных исполнителями превью в страницы одной командой
(`apply_out.py --build`), не открыв ни одной страницы. В этих превью второй экран был
собран как «другой» экран: в теле текстовая выжимка, компонент — в шторке. Живые
страницы заменились, владелец увидел «интерфейсы разные» и «в кнопке ни одной кнопки».
Дальше я «починил» тем, что скопировал левый экран в правый: интерфейсы стали
одинаковыми, но вариант «компонент в шторке» исчез, а в шторке остались текстовые строки.
Реакция: «Ты сделал одно и сломал другое», «Зачем ты переписывал и заменял экраны», «Я не
просил ничего менять в экран». Откатить было нечем — `components-mobile` своего git не имел.

Правила, которые из этого следуют:

1. Массовое вливание подготовленных файлов — только после того, как открыта и
   просмотрена ОДНА страница с новым содержимым (скриншот + замер DOM), а не после
   проверки скриптом, который смотрит только разметку.
2. Плохое превью не «починять» копированием соседнего экрана — пересобирать по образцу
   живого эталона (Checkbox): один и тот же интерфейс на двух экранах, компонент виден
   И в теле, И в шторке настоящей разметкой ДС, правый экран помечен `data-preview="edit"`
   и меняется полями «Правка».
3. Git-снимок — ДО любой массовой правки; без него откат невозможен.
