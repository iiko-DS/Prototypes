# Кнопки в строке на мобиле заполняют строку (fill) — Button group_mob

Когда нужен файл: владелец говорит «кнопки на мобиле заполняют всю ширину строчки»,
«у них будет fill по ширине», «если стоят две кнопки и они влезают в строчку, обе
растягиваются», либо страница/макет показывает кнопки, которые должны делить строку поровну.

## Правило и где оно живёт

`components-mobile/components/Button_DS/button-group-mob.css` + строка
`@import "Button_DS/button-group-mob.css";` в агрегаторе `components-mobile/components/index.css`:

```css
[data-mode="mobile"] .ds-btn--full-width { width: 100%; }
[data-mode="mobile"] .ds-btn-group--horizontal > .ds-btn { flex: 1 1 0; min-width: 0; }
```

- Ширина кнопок числами не задаётся: строку делит flex, ширина — производная (одна кнопка 100 %,
  две и больше — поровну).
- `.ds-btn--full-width` в десктопной библиотеке **не существует** — класс жил только в
  `components-mobile/prototypes/button-modes.html` и ничего не делал (демо «На всю ширину
  (Bottom action bar)» показывало кнопку по содержимому). Реализован он именно мобильным слоем.
- Десктоп остаётся HUG (`.ds-btn` — inline-flex без ширины), в ряду кнопки своей ширины.

## Источники (не выдумано)

- `components-mobile/desktop-to-mobile-plan.md`, строка **Button**: «опция «на всю ширину» в футерах форм».
- Макет «Склад_Заказ-товаров» (узел `5581:31479`): `Button group_mob` = 2 × 175,5 + 8 (gap) = 359,
  то есть вся строка; `Bottom action bar_mob` — кнопка на всю ширину.
- Десктопная проверка — замером (ниже), а не на глаз: «на десктопе ничего не поменялось» —
  это утверждение, которое надо подтвердить числами.

## Капкан №1 — группа сжимается по содержимому (сторона страницы)

`.btnbox{display:flex;flex-direction:column;align-items:flex-start}` в каркасе `build.py` делает группу
flex-элементом по содержимому: правило ДС внутри неё отрабатывает (кнопки равны), но строка не заполняется
(105,9 + 105,9 вместо 159,5 + 159,5). Лечится строкой каркаса `.btnbox .ds-btn-group{width:100%}`.

## Капкан №2 — демо/страница без мобильного агрегатора

`components-mobile/prototypes/button-modes.html` не подключала `../components/index.css`, и её «мобильная»
панель молча не грузила ни одного мобильного файла. Если демо противоречит правилу мобильного слоя —
СНАЧАЛА проверить эту строку подключения, и только потом искать ошибку в CSS.

## Что убрать из каркаса

Своя обёртка `.btnfull` (`.btnbox .btnfull .ds-btn{width:100%}`) больше не нужна: кнопка получает
`ds-btn--full-width`. Владелец читает такие хаки как «не всё подтянулось из дизайн системы» — поведение
должно быть правилом ДС, а каркас страницы ссылаться на класс, а не повторять его эффект.

## Строка в таблице «Что меняется на мобиле»

`Ширина в строке` — Desktop: «по содержимому (HUG) — в ряду кнопки своей ширины»,
Mobile: «заполняет строку (fill): одна кнопка — 100 %, две и больше — делят поровну».
Поля «Правка» у такой строки нет: правится поведение, а не число.

## Те же правила в примерах паттернов на странице рекомендаций

Строку заполняют не только кнопки в макете, но и примеры паттернов (каркас `build.py`):
`.btnbox > .ds-btn{width:100%}` — одна кнопка в слоте на всю строку;
`.pat__phone-row .ds-btn{flex:1 1 0}` — строка делится поровну (было `1 1 auto`: заполняло,
но неравномерно — 121 / 90 / 99,7). Инлайновые `style="flex:1 1 auto"` в `example_html` убирать:
это то же правило, но мимо ДС (было 172,4 + 146,6 → 159,5 + 159,5). Не выравнивать сознательные
исключения: иконка-кнопки, демо тач-зоны `.pat__hit`, узкий `.pat__narrow` 180 px.
Замеры по 20 паттернам и метка тапа (кружок 44 px поверх кнопки) — skill `iiko-design-system`,
`references/recommendation-page-blocks-and-previews.md`.
