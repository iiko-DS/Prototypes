# Совпадение нашего HTML с макетом Figma по числам (сверка замером)

Когда владелец присылает ссылку на узел Figma («вот так у нас отображается …») или говорит
«отрисовал ты не очень хорошо, есть косяки, например с отступами» — наш экран должен совпасть с
макетом по геометрии, а не «примерно похоже». Проверено 16.09.2026 на KDS «режим по блюдам»
(файл Web-KDS-Экраны, узел 9293:16037; у нас — `Prototypes/KDS/multi-shop.html`).

## 1. Снять макет

- Файл должен быть активной вкладкой Figma desktop. По ссылке `?node-id=9293-16037` id идёт через
  дефис, в вызовах — через двоеточие: `9293:16037`. Если владелец дал ссылку, выделение просить НЕ надо.
- Клиент: `python <iiko-ds-components>/scripts/figma-mcp.py call get_metadata --node 9293:16037 --json-out meta.json`
  — габариты, состав, `hidden` слои. В консоль не печатать: кириллица в именах слоёв приходит как
  U+FFFD (ломается в самом ответе MCP, `--json-out` это не лечит). **Тексты и подписи берём со скриншота,
  боксы (габариты и состав) — из метадаты, а отступы, зазоры и радиусы — из `get_design_context`
  по мелким узлам (см. §2: метадата этих значений не содержит вовсе.**
- Скриншот: `... call get_screenshot --node 9293:16037 --json-out shot.json` → base64 декодировать в PNG.
- **Скриншот узла приходит в масштабе**: кадр 1280 × 800 → PNG 1024 × 640, то есть ×0.8. Любой пиксель
  снимка = 1.25 px кадра; все замеры с картинки делить на 0.8.

## 2. Точные значения — из `get_design_context` (а НЕ из пикселей)

Главный урок 16.09.2026: пиксельные догадки и метадата дают **только боксы**, а паддингов, зазоров и
радиусов там нет — на этом владелец поймал три раза («вёрстка летит», «не соблюдаешь отступы внутри
блюда и вокруг, между блюдами, радиусы»). Отступы и радиусы берутся из reference-кода Figma:

```bash
python <iiko-ds-components>/scripts/figma-mcp.py call get_design_context --node 9293:16116 --json-out ctx.json
```

Вызывать **на мелкие узлы** (строка, Content Block, плашка, кнопка) — на большом кадре инструмент
отваливается по таймауту, а на узле отвечает за секунды. В ответе — Tailwind-подобные классы с
переменными; это и есть эталон. Значения узла 9293:16037 (Web-KDS, режим «по блюдам»):

| элемент | Figma |
|---|---|
| строка 1240 | `bg #121212` (`card-food/kds-back-card`), `rounded 12`, `overflow-clip`, высота 80 |
| мета 360 | `bg #121212`, `padding 8`, `gap 8`, `border-right 1px #333`, `drop-shadow 0 4px 2px rgba(0,0,0,.25)` |
| мета верх (48) | паддинг 8 вокруг, контент 32 (время + номер заказа) |
| мета низ (32) | строка 24, паддинг 8 по бокам и снизу |
| тело 880 | `padding 8`, `gap 4` |
| плашка блюда | `bg #212121` (`food-list/background`), `rounded 12`, ровно 864 (текст 808 + кнопка 56), высота по кнопке 56 |
| название | блок `h-40`, отступ 24 от левого края тела (8 паддинга + 16) |
| модификаторы | `pl-34 pr-12 py-4`, зазор 4 |
| кнопка | 56 × 56, `bg #424242`, `rounded 12`, значок 28 (в высокой строке 56 × 116) |
| между строками | строка 80 + зазор 8 → шаг 88 (в макете строки стоят 0 / 88 / 176) |

Каждый пункт закрывать замером своего DOM: `getComputedStyle` для паддингов/радиусов/цветов,
`offsetWidth/offsetHeight` для габаритов (transform сцены на них не влияет).

## 3. Пиксельный замер скриншота — только как перекрёстная проверка

Метадата + скриншот годятся, чтобы понять состав и ритм, но **не** чтобы повторить вёрстку: радиусы и
внутренние паддинги так не снимаются, а ошибка в 8 px видна владельцу сразу. Что здесь всё же полезно:
в тёмной теме KDS зоны различаются заливками — `#333333` фон ЭКРАНА (он же виден в зазорах между
карточками: контейнер списка заливать нельзя), `#121212` сама карточка-строка (мета), `#212121` плашка
содержимого (название блюда), `#424242` подложка кнопки, `#ffab40` /
`#ff5252` «скоро просрочка» / «просрочено». По ним проверяют: полосы строк ищем сканом по столбцу,
края плашки — сканом по строке, шаг строк — по разнице начал полос, зазор — как разницу шага и высоты
плашки. Всё с картинки делить на 0.8 (кадр 1280 × 800 → PNG 1024 × 640).

**Отдельно проверять фоны и зазоры** (срез по столбцу в зоне зазора). 16.09.2026 владелец: «это по сути
такие же карточки как в по заказам, только растянулись: у самих карточек фон чёрный, между карточками
отступы, у экрана фон серый». Эталонный замер: зазор между 1-й и 2-й карточкой (кадр 152…160) =
`rgb(51,51,51)`, слева от списка = `rgb(51,51,51)`, внутри карточки (мета) = `rgb(18,18,18)`,
плашка блюда = `rgb(33,33,33)`. У нас до правки список был залит `#121212` — зазоры стали чёрными,
карточки слились в полосы; после снятия заливки все четыре значения совпали с макетом.

## 4. Замерить свой рендер

Скриншотом свои числа НЕ мерить: сцена авто-масштабируется под ширину окна. Мерить DOM-ом в headless:
`offsetWidth` / `offsetHeight` (не зависят от transform), `getBoundingClientRect()` для расстояний
между элементами, `getComputedStyle()` для паддингов и цветов, `scrollWidth` / `clientWidth` для
прокрутки. Пробу вставлять inline в конец `<body>` — тогда `--screenshot` снимет уже нужное состояние;
состояние задавать **синхронно** (правкой переменных прямо в копии файла), а не через `setTimeout`.

## 5. Ловушки, на которых уже спотыкались

- **Устаревшая заготовка в Temp.** Скриншот из старой копии показывал отменённое состояние —
  владелец пришёл с претензией на то, что уже исправлено. Копию пересобирать из актуального файла
  ПЕРЕД каждым снимком (после правки CSS — заново).
- **`gap` не на том элементе.** Если строки лежат во вложенном `div`, зазор на внешнем контейнере не
  применяется: шаг остаётся равен высоте строки. `gap` ставить на сам список строк.
- **Переменных панелей не хватает.** В панелях цехов нет `--kds-text` (есть `--kds-surface`, `--kds-row`,
  `--kds-ic-*`): `color:var(--kds-text)` молча не применяется и цвет наследуется от страницы — текст
  становится тёмным на тёмном. В панелях белый задавать прямо (как в `.dish`).
- **Плашка меньше тела.** В макете это два блока: тело `padding 8` без фона и внутри него плашка со
  своей заливкой и радиусом 12 (`Table content`). Проще всего повторить именно так — отдельным
  элементом с фоном. Костыль `background-clip:content-box` на теле тоже работает, но заливка тогда
  расползается на паддинг (у нас выходило 72 вместо 56), и его тяжело объяснить следующему агенту.
- **Прокрутка.** Сказано «горизонтальной нет, вертикальная есть» — значит проверить
  `scrollWidth == clientWidth` у своего контейнера (у нас холст растягивался под ленту карточек),
  погасить полосу ленты и сделать холст ровно по ширине макета; список строк должен реально скроллиться.
- **Подписи времени не должны липнуть к кнопке строки.** Кнопка 56 px у правого края — подпись минут
  ставить `right: 64–72px`, иначе она наезжает на числа («0/2» + «−5 мин» читались как каша).
- Прежде чем показывать владельцу «готово», прогнать замеры макета и свои рядом — он сравнивает числа
и при расхождении в отступах сразу это называет.

## 6. Структурные правила владельца (соблюдать вместе с числами)

- **Адаптив не переносит элементы между блоками.** «Это адаптив, там структурно ничего особо не
  ломается. И если были иконки у блюда, они и в адаптиве там же.» Мобильная версия — то же содержимое,
  переставленное по ширине: у блюда остаются иконки цехов, метка гостя, время варианта, название,
  модификаторы, кнопка; в мете заказа — время/плашка просрочки, номер, гость-заказчик, стол.
  Ошибка, которую ловили: иконки цехов и метка гостя уехали в верхний блок заказа.
- **«Покажи больше вариантов» = разложить по СУЩЕСТВУЮЩИМ местам**, а не добавить карточку/заказ/блюдо:
  «Я просил не карточки добавить, а по тем карточкам что уже были раскидать те изменения… чтобы они не
  в одной карточке были, а в 2–3. Не рядом стояли заказы также.» У нас свои строки дописываются в две
  чужие карточки через одну от нашей (индексы 0, 2, 4), своим отрисовщиком, чтобы кнопка жила в общем
  состоянии и показывала выбранный вариант.
- **Просьбу выполнять сразу везде**, где она применима: «убрать строку» — во всех вкладках и на экране,
  а не в одной (владелец: «Ты не везде удалил»).
- **Просрочка у блюда — только полоса 4 px слева.** Никакой линии по нижнему краю или периметру
  (вариант 2 на этом попался дважды: сначала полоса-«фитиль», потом периметр). Время — минуты в строке,
  подпись ставить левее кнопки 56 px с зазором 8.
- **Снимок делать только из актуального файла** и не оставлять старых картинок с отменёнными
  состояниями в папке макетов — по ним владелец приходит с претензией.

## 7. У мобильной версии — СВОЙ узел в Figma, и «верни как было»

16.09.2026 владелец прислал отдельной ссылкой вертикальную (мобильную) строку «по блюдам» — узел
`9317:12970` в том же файле. Вывод: **не адаптировать десктопную строку самому** — у мобильной версии
в макете есть свой узел, и значения надо снимать `get_design_context` по нему (одинаково для любого
«сделай как тут»).

Значения узла 9317:12970 (вертикальная строка):

| элемент | Figma |
|---|---|
| строка | `bg #121212`, `rounded 12`, `overflow-clip`, `flex-col` |
| мета (сверху, `w-full`) | паддинг 8, `gap 8` |
| время | **плашка** `bg #333`, `px-6`, `rounded 12` (в десктопной строке время идёт текстом) |
| номер заказа | справа в строке с временем (`justify-between`) |
| гость / стол | вторая строка 24: гость слева, **стол справа** (`justify-between`) |
| плашка блюда | `bg #212121`, `rounded 12`, **`w-full`** |
| кнопка в плашке | **56 × 56**, `bg #424242`, `rounded 12`, значок 28 у правого края — не растягивать |

**Урок про «верни как было».** На «все блюда растягиваются на всю ширину» я сам придумал
двухколоночную мобильную строку (мета колонкой 112) → владелец: «Какая блядь 2 колончаня. Верни как
было и кнопку просто растяни на всю ширину. И всё.» Если сказано «верни как было» — откатывать
предыдущую структурную правку ЦЕЛИКОМ и не подсовывать свой компромисс вместо этого.

**Свежий макет отменяет прежнюю устную просьбу.** После «сделай как тут» (узел с кнопкой 56 × 56)
прежнее «растяни кнопку на всю ширину» не действует: ориентир — макет, а не память о формулировке.
Когда просьбы идут вразнобой (ширина → колонки → «как тут»), это признак, что нужен узел из Figma:
просить/искать макет, а не угадывать компромисс.

Правила владельца по датам — `references/kds-sketches-owner-rules.md`.
