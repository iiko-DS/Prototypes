# Отчёты владельцу файлом (PDF) и разбор чужих репозиториев

Проверено 14.09.2026: разбор `github.com/plugin87/ux-ui-agent-skills` + PDF-отчёт по нему.
Владелец: «ок. Можешь это в пдф файл оформить?» — то есть анализ в чате он принял, а дальше
захотел файл. Такие задачи повторяются: разбор чужой ДС/скилла/репозитория и отчёт файлом.

## 1. PDF из HTML через headless Chrome (машина Windows, без pandoc/weasyprint)

Скилл `pdf` прямо говорит: для пиксель-в-пиксель HTML→PDF брать headless-браузер, а не reportlab.
Chrome на машине есть: `/c/Program Files/Google/Chrome/Application/chrome.exe`
(есть и Edge: `/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`).

```bash
CHROME="/c/Program Files/Google/Chrome/Application/chrome.exe"
"$CHROME" --headless=new --disable-gpu --no-sandbox \
  --user-data-dir="C:/Users/asukharev/AppData/Local/Temp/chrome-pdf-profile" \
  --no-pdf-header-footer --virtual-time-budget=3000 \
  --print-to-pdf="C:/Users/asukharev/Desktop/<имя>.pdf" \
  "file:///C:/Users/asukharev/AppData/Local/Temp/ds-report/<имя>.html"
```

- `--user-data-dir` — **свежий каталог**: с общим профилем Chrome отдаёт кэш и/или ругается на
  уже запущенный инстанс. Тот же приём, что для страниц ДС на 127.0.0.1:8899.
- `--no-pdf-header-footer` — иначе печатается колонтитул с датой и `file://`-адресом.
- Пути для нативного `chrome.exe` — прямые слэши `C:/…`; вход — `file:///C:/…`.
- Chrome печатает **результат в stdout** («N bytes written to file …») — по этой строке и проверять,
  что файл записан.

### Где что лежит (правило владельца: в папках ДС — ничего лишнего)

| Что | Куда |
|---|---|
| Готовый PDF (артефакт для него) | `C:\Users\asukharev\Desktop\<имя>.pdf` |
| HTML-заготовка, PNG-страницы для проверки | `%LOCALAPPDATA%\Temp\ds-report\` |
| Что-либо в `components-web` / `components-mobile` / `Prototypes` | ничего |

Путь отдавать полной строкой текстом (клик в ACP не работает), самому файл не открывать.

### Каркас HTML — что реально важно для печати

```css
@page { size: A4; margin: 16mm 14mm; }
body { font-family:'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif;
       font-size:10.5pt; line-height:1.5; -webkit-print-color-adjust:exact; print-color-adjust:exact; }
table { font-size:9pt; border-collapse:collapse; }
td.num { text-align:right; font-variant-numeric:tabular-nums; }
.verdict,.note,.avoid,.kpi,section { break-inside:avoid; } h2,h3 { break-after:avoid; }
```

- **`Segoe UI` первым в стеке**: Roboto из `font.css` ДС на машине может не быть, а кириллицу
  Segoe UI рисует без настройки. Проверено — «квадратиков» нет.
- **`print-color-adjust: exact` обязателен**, иначе цветные плашки (вывод/предупреждение) и фон
  заголовков таблиц не печатаются.
- Таблицы — 9pt, колонки с числами `tabular-nums`; длинные английские пути в `code` переносятся,
  но лучше держать 3 колонки и не уже 9pt.

### Проверка (обязательно перед отдачей файла)

```bash
S="C:/Users/asukharev/AppData/Local/hermes/skills/productivity/pdf/scripts"
python "$S/pdf_read.py" "<pdf>" --meta                      # page_count + размер страницы A4 595×842 pt
python "$S/pdf_page_image.py" "<pdf>" --pages 1-N --dpi 100 \
  --out-dir "C:/Users/asukharev/AppData/Local/Temp/ds-report/imgs"
```

Затем PNG смотреть **своим зрением** (vision_analyze): кириллица отрисована, таблицы в полях,
нет обрывов текста, последняя страница не пустая. `page_count` берётся из `--meta`.
Зависимости хелперов ставятся одной командой (на этой машине — с первого раза, без прокси-возни):
`python -m pip install pypdf pypdfium2 pdfplumber`.

Капканы, на которые я наступил:

- `pdf_page_image.py --pages 1-4` при 3 страницах → `Error: pages out of range 1-3: [4]` и **файлы
  не рендерятся вообще**. Сначала `--meta` → `page_count`, потом рендер ровно этого диапазона.
- `--out-dir` нативному Python передавать нативным путём `C:/…`; MSYS-путь он не поймёт.

### Пагинация и занятый файл (вторая сборка, 15.09.2026)

- **`break-inside: avoid` на таблицах даёт полупустые страницы.** Таблица целиком переезжает на
  следующую, а на предыдущей остаётся полстраницы пустоты: первая сборка «устройства ДС» вышла
  6 страниц с провалом, после правки — 5 плотных. Держать `avoid` на `tr` и плашках
  (`.lead/.note/.stop/.chain`), таблицам давать переноситься по строкам. Заголовок таблицы при
  переносе не повторяется (в наших таблицах нет `<thead>`) — это нормально, но шапку в таблице
  держать в первой строке и не длиннее трёх-четырёх колонок.
- **После правки CSS страницы пересобирать PDF и смотреть заново** — pagination сдвигается, и
  «уже проверенные» страницы меняются.
- **Целевой файл бывает занят просмотрщиком.** Chrome: `Failed to write file C:/…/x.pdf: Процесс не
  может получить доступ к файлу, так как файл занят другим процессом. (0x20)`; `cp -f` в тот же путь:
  `Device or resource busy` (удалить не даёт). Порядок: собрать в `%LOCALAPPDATA%\Temp\ds-report\<имя>.pdf`,
  попробовать скопировать поверх, а при отказе отдать `<имя>-v2.pdf` и сказать одной строкой, что прежний
  файл открыт и будет перезаписан после закрытия. Не удалять открытый файл и не изобретать обходы.
- **«Папки с PNG нет» ≠ проба не отработала.** `pdf_page_image.py --pages 1-8` при 5 страницах печатает
  `Error: pages out of range 1-5: [6, 7, 8]` и не создаёт каталог вовсе. Всегда `--meta` → `page_count` →
  рендер ровно этого диапазона, и только потом смотреть картинки.

## 2. Разбор чужого репозитория/скилла — дерево, а не чтение README

```bash
curl -s "https://api.github.com/repos/<owner>/<repo>"                                  # описание, default_branch, size, license
curl -s "https://api.github.com/repos/<owner>/<repo>/git/trees/<branch>?recursive=1"  # все пути + размеры
```

Лучше в `execute_code`: `urllib` + `collections.Counter` по первым 1–2 сегментам пути. 428 файлов
(5,5 МБ) приходят одним ответом; `truncated: false` проверять — если `true`, дерево порезано и надо
идти по подпапкам. Точечное чтение — `raw.githubusercontent.com/<owner>/<repo>/<branch>/<path>`
(README, CONTEXT, `package.json`, 2–3 файла той папки, ради которой разбор). Весь репозиторий
в контекст не тянуть.

Что из дерева видно сразу и что докладывать:

- **Таблица «папка → файлов → что это»** с абсолютными цифрами (файлы, КБ) — не «много папок».
- **Что из этого вообще не про продукт**: инструкции для агента (`.claude/`, markdown-промпты),
  тесты и фикстуры, npm/CI-инфраструктура публикации, чужая библиотека стилей. У плагинов
  на «любой проект» это 90 % объёма и оно нам не нужно.
- **Есть ли там файл-сборщик вообще.** В `ux-ui-agent-skills` «сборка прототипов» = правила
  (`workflows/prototyping.md`) + 30 гейтов-проверок; сами прототипы пишутся руками
  (`examples/component-states/*.html`), генератора нет. Единственный настоящий билд —
  `scripts/build_tokens.mjs` (токены JSON → CSS). У нас, наоборот, генератор есть (сборка страниц из данных).

## 3. Форма ответа «нужно ли нам так же» (зашла, владелец сказал «ок»)

1. **Короткий ответ блоком** («Нет.» + почему) — первым, до всего анализа.
2. Что за репозиторий: цифры + таблица состава.
3. Где у них то, о чём спросили (и существует ли оно там вообще).
4. Таблица **«их папка → наш аналог → нужно ли нам»** — сравнение по функции, не по форме.
5. Наши цифры: что уже есть (строки/файлы/КБ), чтобы «мы отстаём» не читалось на веру.
6. **Что взять** — 1–3 пункта, каждый маленький и с указанием, что для него не нужны новые папки.
7. **Чего не делать** — отдельным блоком.
8. В конце — одна строка: если под вопросом имелось в виду другое (напр. генератор экранов
   по JSON-описанию), это отдельная задача, вот как она ляжет. Он это читает как «работа начата».

Внизу отчёта — источник цифр: адрес API, коммит (`f947815…`), дата, локальные пути. Цифры в тексте
и в PDF должны совпадать: я считал их одинаковыми командами (`grep -c`, `wc -l`, `ls | wc -l`),
а не пересказывал по памяти.
