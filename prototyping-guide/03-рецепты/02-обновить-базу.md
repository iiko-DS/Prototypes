# Обновить базу и посмотреть страницы

Когда нужно: первый раз запускаешь страницы, вернулся после паузы, или что-то «не сходится» с тем, что показывают коллеги.

## Порядок

```
python pull.py      # забрать свежий main из всех четырёх репозиториев
python doctor.py    # проверить окружение: Python, папки, адреса, собраны ли страницы
python start.py     # собрать страницы и открыть сервер
```

Дальше открыть адрес, который напечатает сервер, обычно:

```
http://127.0.0.1:8899/components-mobile/prototypes/recommendations/index.html
```

Остановить сервер — `Ctrl+C` в терминале.

## Что делает каждая команда

- **`pull.py`** — забирает свежий `main` из четырёх репозиториев. Если в каком-то лежат незакоммиченные правки или ты сидишь в своей ветке, он об этом скажет и ничего не тронет — работа не потеряется.
- **`doctor.py`** — ничего не меняет, только проверяет: версия Python, что это корень папки ДС, что все четыре репозитория рядом и с правильными адресами, собраны ли страницы. Это первое, что стоит запускать при любой непонятной ошибке.
- **`start.py`** — то же, что `build.py` плюс `serve.py`, только в один шаг. `python start.py --no-build` — не пересобирать, только открыть сервер.

## Если pull ругается на local changes

Значит правки лежат в `main`, а не в своей ветке. В GitHub Desktop: `Current Branch → New Branch` — он перенесёт изменения в новую ветку, после этого `main` снова чистый и `pull.py` проходит. Так теряется меньше всего.

## Если страницы собрались без стилей

Папки `components-web` или `components-mobile` нет рядом с `_audit`. Проверить раскладку: все четыре репозитория должны лежать в одной папке, имена папок менять нельзя. Это же покажет `python doctor.py`.
