# Поправить значение компонента

Когда нужно: компонент выглядит не так — отступ, размер, цвет, текст, вариант состояния.

## Что важно понять сразу

**Значение живёт в CSS слоя.** Правим файл компонента: `components-web/components/<Имя>_DS/*.css` (десктоп) или `components-mobile/components/…` + `components-mobile/modes.css` (мобильный слой); слои связаны с Figma-выгрузкой — крупные правки согласуются с владельцем ДС.

## Порядок

1. Обновить базу, чтобы правка не потерялась: `python pull.py`.
2. Завести свою ветку (`Current Branch → New Branch`, имя `ivan/badge-fix`). В `main` не пишем — почему, в [правилах](../02-процесс/совместная-работа.md).
3. Найти нужный файл:
   - **мобильный слой** — `components-mobile/components/…` + токены в `components-mobile/modes.css`;
   - **десктоп** — `components-web/components/<Имя>_DS/*.css` (отдельный репозиторий, но в той же папке рядом).
4. Изменить значение — только в файле слоя ДС.
5. Проверить результат в браузере на своих страницах и прототипах.
6. Описать правку в коммите по-человечески: что и почему. «Поправил отступ» хуже, чем «Badge: отступ 4 → 8, по спецификации ДС».
7. `Push origin` и Pull Request в `main` — по [рецепту «предложить правку»](03-предложить-правку.md).

## Частые ошибки

- Правили чужую копию страницы вместо слоя ДС — такая правка живёт до первой пересборки: переносим в слой ДС.
- Правили значение и в слое, и копией в прототипе — правку оставляем только в слое ДС.
