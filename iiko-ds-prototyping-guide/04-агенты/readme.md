# ИИ-агенты

Когда нужно: работаешь с Copilot, Claude или другим агентом и хочешь, чтобы он собирал интерфейсы из компонентов ДС, а не из самодельных стилей.

## Зачем это здесь

Агент по умолчанию делает «как выглядит на макете»: пишет свои классы, подбирает цвета и отступы на глаз. В ДС так нельзя — вид компонента задаёт сама система, а не макет. Правила ниже описывают это один раз, и агент перестаёт изобретать вёрстку.

## Что где

| Файл | Для кого |
|---|---|
| [`AGENTS.md`](AGENTS.md) | универсальный формат: его читают многие агенты и инструменты |
| [`CLAUDE.md`](CLAUDE.md) | Claude Code (он ищет именно этот файл) |
| [`copilot-instructions.md`](copilot-instructions.md) | GitHub Copilot в VS Code; рабочая копия лежит в корне папки ДС — `.github/copilot-instructions.md` |
| [`skills/`](skills/) | скиллы: подробные знания по ДС, подключаются в агент как навыки |

## Как подключить

- **Copilot в VS Code** — ничего делать не нужно: файл `.github/copilot-instructions.md` уже лежит в корне репозитория `DS` и подхватывается автоматически, когда рабочая папка открыта целиком.
- **Claude Code** — положить `CLAUDE.md` в корень рабочей папки ДС (или дать агенту ссылку на этот файл).
- **Другие агенты** — указать `AGENTS.md` как файл инструкций проекта.
- **Скиллы** — это папки с `SKILL.md` внутри: агент читает такой файл, когда задача подпадает под его описание.

## Что внутри скиллов

| Скилл | Про что |
|---|---|
| `skills/iiko-ds-components/` | компоненты ДС в работе: раскладка и переполнение, состояния кнопок, иконки, мобильный слой, страницы рекомендаций, механизм ревью |
| `skills/iiko-design-system/` | устройство системы целиком: токены, спецификация, правила применения, разбор реальных экранов |

Скиллы — те же документы, что и остальная база: их можно и нужно поправлять через Pull Request, когда нашли неточность.
