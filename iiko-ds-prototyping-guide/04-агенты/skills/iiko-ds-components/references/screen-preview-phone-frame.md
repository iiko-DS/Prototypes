# Блок «На экране» — превью компонента в корпусе телефона (12.09.2026)

Запрос владельца: «Нам теперь нужно какое-то внятное превью того как это выглядит на экране мобилы в
интерфейсе. Пока не знаю как сделать. Есть предположения?» — и выбор из трёх предложенных вариантов:

- **A** — телефонная рамка вокруг той же мобильной панели (быстро, но компонент остаётся изолированным);
- **B** — **экран-контекст из компонентов ДС** внутри рамки: шапка, контент, футер, а наш компонент стоит на своём
  месте. **Это и выбрано** («Давай B»);
- **C** — мобильные версии его реальных экранов (`iiko-ds-prototypes/metro-general-settings.html`, `add-fasovka.html`,
  прайс-листы) — самый честный, но это пересборка экранов, отдельная работа. Не начинать без его слова.

## Устройство

- Данные: необязательное поле `preview_html` в `_audit/rec/data/<slug>.json` (как `found_html`/`result_html` —
  вставляется как HTML, не через `esc()`).
- Генератор: `page()` рисует `<div class="card">\n    <h2>На экране</h2>\n%(preview_html)s\n  </div>` **сразу под
  панелями** `.compare` и выше таблицы «Что меняется на мобиле».
- Каркас (константа `CSS` в `_audit/rec/build.py`):`.phones` — flex-ряд (`gap:20px`, `flex-wrap`, `align-items:flex-start`);
  `.phones__item` — колонка «корпус + подпись»; `.phone` — корпус 375 px, `padding:8px`, фон `#1f1f1f`,
  `border-radius:40px`, тень; `.phone__screen` — `position:relative`, `flex`-колонка, высота 720 px, `overflow:hidden`,
  фон `#f4f5f7`, radius 32; `.phone__status`, `.phone__head`, `.phone__title`, `.phone__body`, `.phone__row`,
  `.phone__foot` — статус-бар, шапка, контент, футер; `.phone__scrim` + `.phone__sheet` + `.phone__sheet-title/-text`
  для шторки снизу; `.phone__actions` — кнопки в столбик на всю ширину.
- **Экран помечен `data-mode="mobile"`** — именно поэтому внутри работают и мобильные значения ДС, и правила из
  `#live`: правка полей в таблице меняет кнопки и в панели, и на всех экранах (один документ, один селектор
  `[data-mode="mobile"] .ds-btn`).

2. **Выбор и фильтры** — «Стоп-лист»: сверху строка из **четырёх кнопок в одну линию** (иконка+текст · только текст ·
   текст+иконка справа · только иконка), ниже `.ds-tabs` (Все / В наличии / Стоп), `.ds-chips` ×3, `.ds-checkbox` ×3,

Итого 11 компонентов ДС на трёх экранах: Search, List, Form field, Tabs, Chips, Checkbox, Slide toggle, Radio,
Divider, Button, Button icon. Разметка каждого берётся из примеров его страницы (`data/<slug>.json`), не сочиняется.
Проверено замером: правка «Высоты» меняет **все 9** `.ds-btn` на экранах (44 → 40) вместе с мобильной панелью,
а `ds-btn-icon` (40 × 40) не меняется — это другой компонент, и об этом надо сказать прямо.

## Капканы, которые уже сработали

- **Подпись — только вне корпуса.** `<p class="phone__caption">` должен лежать в `.phones__item` рядом с `.phone`,
  а не внутри него: внутри она рисуется прямо по чёрной рамке корпуса (сначала я закрыл `.phone` после подписи).
- **Инлайн-стили в экран не тащить.** Полноширинные кнопки в контенте получаются классами каркаса
  (`.phone__actions .ds-btn{width:100%}`, `.phone__foot .ds-btn{flex:1 1 0}`), а не `style="width:100%"`;
  у `.ds-input` пример из данных с `style="width:320px"` для превью тоже лишний — в колонке `flex` поле растягивается само.
- **Соседние компоненты — только готовой разметкой из примеров.** `.ds-input` (Form field) и `.ds-checkbox`
  скопированы из `data/form-field.json` и `data/checkbox.json`; свои классы не выдумывать, иначе превью противоречит ДС.
- **Пустой экран выглядит недоделанным.** С двумя строками контента в корпусе на 720 px остаётся большое пустое поле —
  добавить 2–3 строки, чтобы экран читался как интерфейс.
- **Плашки автогена в корпусе — правила каркаса были только для панелей.** Нейтрализация «background = color»
  в `rec.css` записана как `.panel .ds-list-item__text, …{background:none}`, а экран живёт **вне** `.panel`, поэтому
  подписи строк списка рисовались чёрными прямоугольниками. Лечение — в `build.py` после закрывающей `"""` константы
  `CSS` дублировать эту строку с заменой `.panel ` → `.phone `:
  `_plates = [ln for ln in CSS.split("\n") if ln.startswith(".panel .ds-checkbox-label__support-text")]` →
  `CSS = CSS.replace(_plates[0], _plates[0] + "\n" + _plates[0].replace(".panel ", ".phone "), 1)`.
  Любой новый блок вне `.panel` (экран, врезка, рамка) тянет за собой те же артефакты — проверять их скрином, а не логикой.
- **Вставку Python-кода легко положить ВНУТРЬ CSS-литерала.** Я вставил блок `_plates = …` после первого
  подходящего якоря — а якорь (`.panel .ds-dialog-view__action…`) был внутри тройной CSS-строки, поэтому код уехал
  в `rec.css` текстом, а правило для `.phone` не появилось. Порядок: все трансформации CSS — **после закрывающих
  `"""`**; проверка — `grep` по `rec.css` на нужный селектор И на мусор (`_plates`).
- **У контейнера списка ширина из библиотеки — 258 px, мобильного значения нет.** `.ds-list-container`
  (`iiko-ds-web/components/List_DS/list-ontainer.css`) задаёт fixed width, поэтому в корпусе он уже остальных
  блоков (327). Это не дефект превью, а факт ДС: либо доложить владельцу как находку (так и сделано), либо
  растянуть правилом каркаса `.phone .ds-list-container{width:100%}` — только по его слову.
- Иконки — только легатуры Material Icons (размер через `font-size`), как на всех страницах; скрин с
  `--virtual-time-budget` ≥ 10000, иначе легатуры попадут в кадр словами.

## Кнопки в одну строку: бюджет ширины (замерено)

Экран 375 px даёт внутренние **359 px**; строка кнопок (`display:flex;flex-wrap:nowrap;overflow-x:auto`, класс
`.phone__line`) со стандартными отступами строки (`padding:12px 16px`, `gap:8px`) четыре кнопки **не вмещает**:
контент 362 px против 359 — последняя иконка-кнопка обрезается наполовину и строка едет скроллом.
Рабочие значения найдены подбором по замеру: **`padding:8px 10px` + `gap:4px`** → ровно 359 px, четыре кнопки
(M 121 px «➕ Создать», M 54 px «ОК», M 106 px «Далее ›», Button icon 40 px) стоят в одну линию без обрезки.
Замерять надо `line.clientWidth` против `line.scrollWidth` (совпали — влезает), а не глазами.
Полное правило «сколько кнопок влезает и что делать, когда не влезает» и цитаты платформ —
`references/button-rows-and-overflow.md`.

## Проверка

Синхронный пробник на страницу: в `onload` ввести значение в поле «Высота» и замерить кнопки в панели, на каждом
экране и в десктопной панели. Замер `button.html` (ввод 40):

| | до | после |
|---|---|---|
| мобильная панель (10 кнопок) | 44 | 40 |
| экран 1 «футер» (ширины 160/160) | 44 | 40 |
| экран 2 «контент» (ширина 327) | 44 | 40 |
| экран 3 «шторка» (327) | 44 | 40 |
| десктопная панель | 36 / 28 / 24 | без изменений |
| колонка Mobile | `44 px` | без изменений |

Плюс скрин блока и пиксельный поиск корпуса (цвет `#1f1f1f`) для кропа — глазами проверять, что подписи под
корпусами, пустот нет, иконки отрисованы значками.

## Расширение на другие компоненты

Экран нельзя вывести из данных — его собирает агент, поэтому в плане были 3–4 переиспользуемых экрана:
(1) список с фильтрами, (2) форма с футером, (3) шторка/диалог, (4) настройки. Для каждой страницы берётся тот экран,
где компонент реально живёт; `preview_html` живёт в данных страницы, каркас и связь с «Правкой» — общие.
Содержимое экранов на `button.html` — заглушка; владелец сказал, что назовёт сценарии и тексты сам.
