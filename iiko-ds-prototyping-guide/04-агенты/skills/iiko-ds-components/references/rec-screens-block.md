# Страница компонента: блок «На экране» новым видом (13.09.2026)

Эталон — `components-mobile/prototypes/recommendations/button.html`.
**14.09.2026 вид раскатан на все 38 страниц** (`python _audit/rec/build.py` пересобирает все
сразу; оболочка `index.html` — тем же прогоном). У старых данных вид был другой (табы
«Паттерны поведения» + таблица «Что|Правка» рядом с экранами) — эти файлы уже пересобраны,
откатывать их по отдельности нельзя: `rec.css` общий и новые правила нужны всем страницам.
Оценки, комментарии и значения на страницах теперь собирает механизм ревью —
`references/rec-review-mechanism.md`.

Как раскатка прошла по старым данным (важно, если данные компонента будут пересобирать с нуля):

- у старых `preview_html` **уже два** `data-mode="mobile"` (две копии одного экрана с подписями
  «…как рекомендовано» / «То же, с правками из таблицы справа») — генератор берёт их как есть,
  но теперь ещё и навешивает `data-preview="edit"` на ВТОРОЙ экран (раньше на старых данных
  правки из 4-й колонки не делали вообще ничего — правило правки привязано к этому атрибуту);
- контейнеры кнопок старой разметки размечаются слотами: `class="phone__actions"` →
  `data-buttons="screen"`, `class="phone__foot"` → `data-buttons="sheet"`;
- **режим показа примера выбирается по каждому паттерну** и записан в наборе (`data-kind`):
  пример-набор кнопок (`slot`) встаёт в слоты, как у Button; пример-состояние компонента
  (`body` — есть классы `ds-*`, кроме `ds-btn*`: галочки, список, диалог, поле — так у
  большинства компонентов) показывается **вместо тела экрана**, а открытая шторка на время
  паттерна прячется (`.phone__sheet`/`.phone__scrim` → `display:none`), иначе она закрывает собой
  то, что показываем; на «Основные» возвращаются и тело, и шторка.
- прогон раскатки (все 38 страниц): пунктов меню = паттернам, пример меняет экран 3 из 3 (33
  страницы) или 2 из 3 (пять страниц — там примеры паттернов буквально повторяются), возврат
  «Основные» ок, статусы/комментарий/«Сбросить» есть, заголовок паттерна есть, переполнение 0 px.
- найдено рядом (не чинил): 88 пар паттернов внутри одного компонента с **одинаковым** примером
  (больше всего Card — 11 пар; у Dialog первые три паттерна рисуют один и тот же диалог).

## Итоговая разметка (`build.py`, функция `screens_card(d)`)

- Карточка «На экране» = `.screens` (грид `300px + minmax(0,1fr)`, ≤1250 px — одна колонка):
  слева `.screens__menu` (вертикальный список `.screens__item`, `max-height:780px; overflow-y:auto`),
  справа `.screens__stage` с двумя экранами; под гридом `.screens__note[data-note]`, в конце
  скрытый `.screens__sets[hidden]` с наборами паттернов.
- Экраны: `preview_html` в `data/<slug>.json` — разметка **одного** телефона; `screens_card()`
  клонирует её дважды (`.phones__item` + подписи «Как рекомендовано для мобилы» / «Тот же экран
  с правками из 4-й колонки»), второму экрану подставляет `data-preview="edit"`.
  Совместимость: если в `preview_html` уже два `data-mode="mobile"` (старые данные) — берётся как
  есть, но второй получает `data-preview="edit"`, а контейнеры кнопок — `data-buttons` (см. выше).
- Слоты кнопок: `data-buttons="screen"` (в теле экрана — `.btnbox` под карточкой) и
  `data-buttons="sheet"` (в шторке, тоже `.btnbox`). `.btnbox` — колонка с шириной по
  содержимому; полноширинная кнопка заворачивается в `<span class="btnfull">`
  (`.btnbox .btnfull .ds-btn{width:100%}`). Класса `.screens--pattern` больше нет: дублировать
  нечего — в теле экрана одно место под кнопки, а не два (см. «дефолт — правдоподобный экран»).
- Набор паттерна: `<div data-set="pat-<slug>-<i>" data-kind="slot|body">` с частями
  `<div data-part="screen">…кнопки примера…</div>`, `<div data-part="sheet">…</div>`,
  `<div data-part="body">…пример целиком…</div>` и `<div data-part="note">…текст + Источники +
  статусы + комментарий…</div>`. `data-kind` считает генератор: `body`, если в примере есть классы
  ДС не из семейства кнопок, иначе `slot`. Нет `example_html` — части не пишутся, JS оставляет дефолт.
- Плашка паттерна несёт механизм ревью: заголовок, три статуса, «Сбросить» этого паттерна,
  «Свой комментарий» (подробности и ключи — `references/rec-review-mechanism.md`).
- JS: клик по `.screens__item` → активный класс; innerHTML всех слотов из набора; текст в
  `[data-note]`. «Основные» — возврат из сохранённого `base[i]` **по каждому слоту**, а не по
  имени слота: у слотов разные дефолты и порядок в DOM.
- 4-я колонка: `changes_table()` → `Что | Desktop | Mobile | Правка` (поля — `edits_of(c)`, пустая
  ячейка там, где правки нет), приписка «Правка применяется к правому экрану…» — под таблицей.
  Правило правки прежнее: `[data-mode="mobile"][data-preview="edit"].phone__screen .ds-btn…` —
  правится только правый экран, левый держит рекомендованные значения.
- Удалено из `build.py`: `platforms_card()`, `edits_panel()`, скрипт табов и стрелок. Старые CSS
  (`.editrow`, `.edits`, `.pat__bar/.pat__tabs/.pat__arrow/.pat__panel/.pat__ex`) оставлены намеренно —
  они ещё нужны 37 непересобранным страницам.

- Замер эталона (Button, окно 1920, проба; после перехода на реальный экран заказа): слотов 4

## Грабли

- `.screens__note:empty{display:none}` — у дефолта текста нет, без правила остаётся пустой отступ.
- `.btnbox` держит кнопки шириной по содержимому, полноширинную оборачивать в `.btnfull`.
  Не задавать `.btnbox .ds-btn{width:auto}`: правило перебило бы `.pat__phone .ds-btn{width:100%}`
  у примеров паттернов (одинаковая специфичность, а `.btnbox` ниже по файлу) и «кнопка на всю
  ширину» перестала бы себя показывать.
- Стиль ДС «текстовая» кнопка (`--neutral --text`) рисуется с белой заливкой — это сама библиотека
  (`components-web/components/Button_DS/button.css: background: var(--ds-color-button-neutral-default)`),
  а не дефект страницы; на сером фоне телефона выглядит как белая плашка. На странице не «чинить».
- **Не переиспользовать имя класса из каркаса.** Я назвал строку кнопок в меню оболочки
  `.review__row` — тем же классом уже назывался ряд статусов в плашке паттерна; второе правило
  в CSS победило (одинаковая специфичность, ниже по файлу), у плашки появился `flex:0 0 100%`,
  и заголовок паттерна смялся в столбик 76 px вместо 310 («Сломался заголовок и кнопки у описания
  паттерна»). Перед новым классом — `grep` по `build.py` на это имя; после правки — замер
  `getBoundingClientRect` у заголовка и ряда кнопок (должны стоять в одну строку, ряд прижат вправо).
- **Шаблоны страниц форматируются через `%`.** CSS со знаком процента (`width:34%`) роняет сборку
  («unsupported format character»), а `\n` внутри JS-строки, записанный в обычной (не raw) строке
  Python, превращается в реальный перевод строки и ломает скрипт страницы (Chrome молча теряет
  весь обработчик). Для страниц с большим CSS — подстановка токенами (`@@DATA@@` → `.replace(...)`
  — так сделана `_audit/rec/summary.py`), а в JS-строках не писать `\n`: либо без переносов,
  либо `String.fromCharCode(10)`. После каждой сборки: вытащить `<script>` и прогнать `node --check`.
- **Высота мобильной кнопки — только `min-height`.** В `Button_DS/button-touch.css` стояло
  `height:44px`, а у паттерна «Длинная подпись» подпись в две строки: содержимому нужно 45 px
  при рамке 44 — текст вылезал («не учитывает 2 строчку текста»). Исправлено в двух местах:
  `min-height` для `.ds-btn--m/--s/--xs` в мобильном слое и шаблон правки в данных
  (`min-height:@px` вместо `height:@px`) — живое правило правки перебивает слой по специфичности,
  поэтому одного места мало. Тот же приём пригодится любому мобильному контролу с переносимой подписью.

## Дефолтный экран — только по реальным экранам iiko (13.09.2026)

Третий заход владельца: «Нет - ничего правдоподобного там нет. Не бывает такого интерфейса.
Смотри что реально есть в iiko.ru». Правило: **прежде чем рисовать дефолтный экран, найти и
посмотреть реальные экраны iiko**, и собирать из их элементов, а не из своей фантазии.

Где брать референсы (всё читается `curl`-ом, без браузера):

- **iiko.ru** — страницы решений: `curl -sL --max-time 25 https://iiko.ru/solutions/restaurant/`,
  затем вытащить картинки `https://iiko.ru/wp-content/uploads/….(png|jpg|webp)` (превью
  `-150x150`/`-300x300` отбросить). Там лежит, например, `…/2026/05/waiter2.jpg` — живой скриншот
  iikoWaiter: сегмент «Мои заказы | Все заказы», залы (БАР, ВЕРАНДА, ЗАЛ), карточки столов со
  статусом, составом и суммой, нижняя навигация «Заказы | Столы | Действия».
- **App Store** — `curl -sL -A 'Mozilla/5.0' https://apps.apple.com/gb/app/iikowaiter/id641016373`;
  скриншоты лежат по шаблону `…/PurpleSource211/…/<uuid>_1-6.5-en.jpg/600x1300bb.webp` — скачать,
  конвертировать в PNG (PIL) и посмотреть зрением. Оттуда взят реальный приём для кнопок:
  **нижняя панель — сумма слева («$22.50») + главная кнопка справа («Done»)**; и экран заказов
  (карточки столов: номер, время, статус, состав, гости, сумма; кнопка «+» внизу справа).
- **Репозиторий** — `components-mobile/prototypes/button-modes.html`: реальные подписи кнопок iiko
  («Создать», «Далее», «Отмена», «Добавить», «Сохранить», «Удалить») и «Футер формы — на всю
  ширину (bottom action bar)».

Итоговая разметка дефолта (Button, `data/<slug>.json` → `preview_html`, разметка одного телефона):

- шапка: `← «Стол №4»` + `more_vert` иконкой-кнопкой (`aria-label="Действия по заказу"`);
- тело: карточка заказа (статус «Заказ отправлен», «Стол №4 · 4 гостя», сумма 1 900 ₽, состав
  «1 Пепперони · 1 Американо · 1 Сэндвич») + `.btnbox[data-buttons="screen"]` = «＋ Добавить блюдо»
  (обводка, обёрнут в `.btnfull`) и «Печать пречека» (текстом) — оба действия реальные;
- шторка: `.phone__sheet-head` («Стол №4 · 4 гостя», «Заказ отправлен в 13:43», иконка-кнопка «✕»),
  затем `.sheetbar` = `<span class="sheetbar__sum">1 900 ₽</span>` +
  `.btnbox[data-buttons="sheet"]` с **одной** главной кнопкой «Отправить на кухню» (как в приложении).

В дефолте не должно быть warning/disabled, размеров S/XS и «Ещё» — именно они делали экран «свалкой»;
эти состояния живут в паттернах. Строки в шапке/шторке — реальные метаданные («Заказ отправлен
в 13:43»), а не пересказ примера.

CSS узла: `.sheetbar{display:flex;align-items:center;justify-content:space-between;gap:12px}`,
`.sheetbar__sum{font:500 16px/24px 'Roboto',…;white-space:nowrap}`, `.sheetbar .btnbox{flex:0 0 auto}`.
