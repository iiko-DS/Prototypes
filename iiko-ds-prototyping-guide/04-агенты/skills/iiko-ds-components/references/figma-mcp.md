# Figma Dev Mode MCP — как снять числа, которых нет в токенах

Нужно, когда значение живёт только на холсте Figma: `_mob`-компоненты, размеры варианта,
которого нет в `tokens.css`, проверка того, что в макете действительно есть.

Проверено 11.09.2026 на `Figma Dev Mode MCP Server 1.0.0` (порт 3845, Figma desktop).

## Клиент

`scripts/figma-mcp.py` (только стандартная библиотека):

```bash
python scripts/figma-mcp.py tools                        # список инструментов
python scripts/figma-mcp.py call get_metadata             # текущее выделение в приложении
python scripts/figma-mcp.py call get_variable_defs --node 17123:81299
python scripts/figma-mcp.py call get_design_context --node 7408:44703 --json-out ctx.json
```

## Инструменты (6)

| Инструмент | Что отдаёт |
|---|---|
| `get_design_context` | основной инструмент design-to-code: reference-код + скриншот + контекст узла |
| `get_variable_defs` | определения переменных для узла, вида `{'icon/default/secondary': #949494}` |
| `get_screenshot` | скриншот узла (или текущего выделения) |
| `get_metadata` | XML-структура узла (id, name, x, y, width, height) — **без** заливок; для состава и габаритов |
| `get_motion_context` | keyframe-анимации узла |
| `get_figjam` | код для узла FigJam |

`get_metadata` без аргументов возвращает **текущее выделение** — дешёвый способ понять,
какой файл открыт в приложении, до того как о чём-то просить пользователя.

## Что решает успех вызова (и это не nodeId)

1. **Активный документ.** Node id разрешается только внутри файла, открытого в Figma desktop.
   Пока впереди другой файл (например страница с фреймом «Метро»), любой чужой id даёт
   `No node could be found for the provided nodeId: 17123:81299. Make sure the Figma desktop app
   is open and the document containing the node is the active tab.` — id, скопированный из
   шапки компонентного файла (`.ds-btn-icon` → «страница Button icon [17123:81299]»), **не**
   работает при другом активном документе.
2. **Выделение.** Узловые инструменты по умолчанию работают с выделением, поэтому просьба к
   пользователю формулируется узко: «переключи Figma на файл ДС (`Iiko-Web-DS-New-`) и выдели
   `Button toggle_mob`». Не «дай доступ» и не «открой что-нибудь».

## Транспорт (если пишешь свой клиент)

- `POST /mcp`, JSON-RPC 2.0, заголовок `Accept: application/json, text/event-stream`.
- Ответ — **незакрывающийся** `text/event-stream`: `event: message` + `data: {json}`.
  Обычный `read()` висит до таймаута; читать побайтово и останавливаться, когда встретился
  `id` отправленного запроса. Симптом наивной реализации: «ERR timed out», хотя сервер ответил.
- `mcp-session-id` лежит в заголовках ответа на `initialize`; дальше его нужно передавать
  заголовком `Mcp-Session-Id`, а после `initialize` — отправить `notifications/initialized`.
- `POST /mcp` без сессии отвечает `{"error":{"code":-32001,"message":"Invalid sessionId"}}` —
  это нормально, сессии ещё нет.
- **Не печатать сырой результат:** `initialize` и `tools/list` несут base64-иконки на десятки
  килобайт. Печатать только `result.content[*].text`.

## Рабочий порядок для `_mob`-значений

1. Строка компонента в `components-mobile/desktop-to-mobile-plan.md` → колонка `_mob`: «Собран»
   значит, что компонент в Figma есть (`Button toggle_mob`) — числа снимаемы; «нет» значит,
   что источника нет и значение — решение владельца, а не вывод из Material.
2. Попросить пользователя переключить приложение на файл ДС и выделить нужный компонент
   (одно короткое сообщение, конкретное имя компонента).
3. `get_metadata` (габариты и состав) → `get_variable_defs` (переменные узла) → при
   необходимости `get_screenshot`, чтобы посмотреть глазами.
4. Числа писать в `modes.css` как переопределения только отличающихся токенов и подтверждать
   замером в браузере.

## Снятие целого макета экрана (проверено 14.09.2026)

Владелец может сам прислать ссылку вида
`https://www.figma.com/design/<fileKey>/<имя>?node-id=5581-31479` — тогда просить его о выделении
**не нужно**, надо только чтобы этот файл был активной вкладкой Figma desktop (`node-id` из ссылки
пишется через `-`, в вызовах — через `:`: `5581:31479`). Рецепт сборки экрана из такого макета —
skill `iiko-design-system`, `references/default-screen-from-figma-mock.md`.

- `get_metadata --node <a:b> --json-out meta.json` → **`--json-out` работает для любого вызова**, а не
  только для `get_design_context`/`get_screenshot`: кладёт сырой JSON в файл, и его можно парсить питоном
  без консоли.
- ⛔ **На имена слоёв не полагаться: кириллица приходит битой.** 16.09.2026 на файле Web-KDS имена
  пришли с 1424 символами U+FFFD (`Режим по блюдам_…` → `??????? ????????_…`) — и при печати в консоль,
  и в `--json-out`, и несмотря на `PYTHONIOENCODING=utf-8`/`PYTHONUTF8=1`. То есть «прочитать подписи из
  `name`» — **не** рабочий приём; латиница (`Card header`, `Content Block`, `Scroll`, `Footer`) читается,
  кириллица нет. **Тексты и подписи брать только со скриншота** (`get_screenshot` → base64 → PNG →
  посмотреть глазами), а имена использовать лишь как намёк на роль слоя.
- **Раскладку из метадаты снимать скелетом:** распарсить XML и печатать только дерево
  `tag id [x,y W×H]` до нужной глубины — чисел в атрибутах достаточно, чтобы вытащить геометрию
  (например строку экрана «по блюдам»: контейнер 1240, мета 360, контент 880, внутри текст 808 и
  кнопка 56×56 со значком 28×28; высота строки 72 = 56 контента + 8+8 паддинга). Имена при этом не нужны.
- `get_metadata` **без узла и без выделения** отдаёт список верхнеуровневых страниц документа с их id —
  дешёвый способ понять, какой файл открыт в Figma desktop, до просьб к пользователю (имена там тоже битые).
- `get_screenshot --node <a:b> --json-out shot.json` → в файле
  `{"result":{"content":[{"type":"image","data":"<base64>"}]}}`; base64 декодировать в PNG и
  смотреть глазами — это эталон для сборки.
- **Скриншот приходит в масштабе:** кадр 1280 × 800 → PNG 1024 × 640, то есть ×0.8; все замеры
  по картинке делить на 0.8, иначе отступы «не сходятся» на четверть. Как сверять с макетом
  наши числа (заливки-зоны, шаг строк, прокрутка) — skill `iiko-design-system`,
  `references/figma-mock-metric-fidelity.md`.
- **Метадата НЕ содержит паддингов, отступов и радиусов** — только боксы (`x`, `y`, `W×H`). Если
  владелец сверяет наш HTML с макетом «по отступам / внутри и вокруг блока / радиусам», метадаты +
  скриншота НЕ хватает: 16.09.2026 на этом споткнулись трижды — замер пикселей давал 8-пиксельные
  ошибки внутри блока и не давал радиусов вообще, а владелец каждый раз это видел.
- **`get_design_context` вызывать не на кадр целиком, а на МЕЛКИЙ узел.** На большом фрейме он
  отваливается по таймауту (`ERROR: TimeoutError: timed out`, в `--json-out` остаётся 46 байт), а на
  отдельной строке / блоке содержимого / кнопке (`9293:16084`, `9293:16116`, `9293:16118`, `9293:16120`)
  успешно отдаёт reference-код за секунды. Рабочий порядок: `get_metadata` — состав и боксы → по нужным
  мелким узлам `get_design_context --json-out ctx.json` → из классов взять числа и повторять один в один.
- **Что в reference-коде:** Tailwind-подобные классы с переменными — то, что и надо переносить:
  `p-[8px]`, `gap-[8px]`, `rounded-[12px]`, `rounded-bl-[8px]`, `size-[56px]`, `h-[40px]`,
  `border-r border-[#333]`, `bg-[var(--card-food/food-list/background,#212121)]`,
  `drop-shadow-[0px_4px_2px_rgba(0,0,0,0.25)]`. Читать питоном: взять `result.content[0].text`,
  вытащить пары `className` + `data-node-id`/`data-name` и печатать только отфильтрованные классы
  (`rounded|gap-|p[trblxy]?-\[|w-\[|h-\[|bg-\[|border|size-`), узлами — иначе 23 КБ простыни.
  Именно так 16.09 снялись точные значения экрана «по блюдам» (после того как пиксельные догадки дали
  три замечания подряд).
- Метадата на **инстанс** (например `Button`) детей не разворачивает: строки с подписями кнопок
  берутся со скриншота, а не из XML.
- В метадате видно `hidden="true"` у слоёв — по нему понятно, что в макете реально скрыто
  (так ловятся, например, бэкдроп и элементы раскрытых/свёрнутых состояний).
