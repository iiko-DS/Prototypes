# Десктопная половина рекомендаций: чем проверять и что там нашлось (12.09.2026)

Повод. Владелец: «Причём тут мобильная версия? У тебя ошибок полно везде в компонентах в десктопе.
Просто жесть. Ты проверяешь и проверяешь очень плохо. Вообще никак». К этому моменту мобильный слой был
доведён до нуля (`audit-mobile-values.py` — 40/40 OK), то есть отчёт был **верным и бесполезным**: он
описывал половину работы. Дальше — то, что должно было быть в первом же проходе.

## Детекторы (лежат в `_audit/rec/checks/`)

| Скрипт | Что ловит |
|---|---|
| `audit-desktop.py <mode>` | `NATIVE` — нарисован системный `input[type=checkbox|radio|range]` (значит CSS компонента не подключён); `CONTENTBOX` — объявленная `height` не совпала с рендером при паддингах/рамке; `EMPTY`; `SIZEGAP` |
| `audit-live-desktop.py` | `CLIPPED` (scrollHeight/clientHeight), `OVERLAP` (пересечение листовых подписей), `VOID` (пустое поле ≥ 40 px в контейнере с фоном/рамкой), `STATE` (disabled и enabled одинаковы по фону и цвету) |
| `shoot.py <pages> <desktop\|mobile>` | скрин headless Chrome + кроп нужной половины |
| `sheets.py` | листы 2×2 из четырёх страниц с подписью — 38 страниц за ~10 вызовов vision |

Требуют `python serve.py 8899` в корне DS и свежего профиля Chrome. Оба печатают счётчик по каждому виду
находок; «0» — это результат, а не молчание.

### Шаблон, который работает

Страница-обёртка (git-ignored, живёт в `_audit/rec/checks/`) с iframe на каждую страницу,
`f.onload = () => setTimeout(..., 350)`, разбор `f.contentDocument` (same-origin через локальный сервер),
вывод в `<pre id="out">`, чтение через `--dump-dom`. `--virtual-time-budget` не экономить (150000 — норм).

Ловушки, обе пройдены:

- **Строки только через `String.fromCharCode(10)`.** `OUT.join('\n')` внутри Python-шаблона доезжает до
  браузера как реальный перевод строки в строковом литерале → `SyntaxError` → пустой `<pre>`, а скрипт
  печатает «no output -- server up?» и виноватым выглядит сервер. Проверка одной командой: вытащить
  `<script>` из обёртки и прогнать `node --check`.
- **Пустой `<pre>` ≠ «детектор ничего не нашёл».** Пока не проверено, что JS исполнился (например, обёртка
  на трёх страницах печатает `NONE`, если список находок пуст), «no output» нельзя читать ни как «сервер
  лёг», ни как «всё чисто». В одних и тех же симптомах были оба случая.

## Приём «чистая библиотека»: пробник без каркаса

Собери одноразовую страницу (потом удали) в `_audit/rec/checks/`: она линкует только
`font.css → tokens.css → styles.css → components/index.css` (без `rec.css`) и минимальную разметку спорных
классов; скрипт внутри ищет для
каждого элемента **объявленную** `height` по его правилам (`el.matches(rule.selectorText)`) и печатает JSON
в `<pre>`. Так дефект ДС отделяется от эффекта каркаса: каркас лечит box-sizing и min-height, поэтому на
страницах ломающееся в библиотеке выглядит целым — «замер на странице» и «замер на библиотеке» отвечают на
разные вопросы, и в отчёте нужны оба.

## Что закрыто в каркасе (`_audit/rec/build.py`, `data/*.json`)

1. 4 `<link>` на страницу: `Checkbox_DS/checkbox.css`, `checkbox-icons.css`, `Radio-Button_DS/radio.css`,
   `radio-icons.css` → маркер 20 × 20, `gap 8px`, нативный input 0 × 0, цвета состояний на месте.
2. `.panel .ds-btn-icon:disabled` (+ `--outlined`, `--text`) с токенами `--ds-color-button-icon-disable-*` —
   специфичность `.panel` + два класса (0,3,0) бьёт стиль-блок.
3. `.panel .ds-menu-container, .panel .ds-select-container, .panel .ds-list-container { min-height: 0 }`.
4. `.panel .ds-textarea__hint { height: auto }`.
5. Меню рекомендаций — только названия компонентов (без `nav__note`); чип категории остаётся на странице.
6. Переписан лживый текст на страницах Checkbox/Radio («Найдено и починено… добавил 4 импорта») и добавлены
   карточки «Найдено в ДС» на 9 страниц: checkbox, radio, button-icon, menu, select, list, textarea, search, badge.

## Порядок приёмки (снял вопрос «ты вообще не проверяешь»)

`python build.py` → `audit-desktop.py desktop` → `audit-live-desktop.py` → `audit-page-render.py`
(плашки/контраст/выход) → `audit-mobile-values.py` (40 проверок) → скрины и листы обеих половин → сверка
текста страниц с реальностью. Ожидаемый итог здоровой сборки: мобильный аудит **40/40 OK**, десктопные
детекторы **0**, `plates/overflow` **0**, 38 страниц × 2 панели непустые (проверяется счётчиком элементов
в `.panel__body`). Остаются только два контраста — badge warning **1.88** и подпись поиска `#d6d6d6` **1.38**;
это палитра ДС, оба описаны карточкой «Найдено в ДС» и владельцу отданы как вопрос, а не как правка.

## Открытые вопросы владельцу

- 4 импорта в агрегатор `components-web/components/index.css` — одна строка на файл, снимает системный контрол
  в источнике, а не на страницах (ждёт его «да»: библиотека без разрешения не правится).
- Порядок правил в `Button-Icon_DS/button-icon.css`: состояния после блока «Стиль × Тип».
- Контрасты badge warning и подписи поиска — вопрос палитры, не режима.
