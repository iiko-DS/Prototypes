# Страницы «компонент по рекомендациям платформ»

Класс задачи: пользователь просит **не сравнивать с Figma**, а сразу собрать по каждому
компоненту ДС страницу с примерами — только те размеры/варианты, которые реально
рекомендуют первоисточники (Material Design 3, Angular Material, iOS HIG), с настоящими
числами. Триггерная формулировка: «по рекомендациям по каждому компоненту собрать страницу
с примерами, но вывести реальные значения» + пример-образец («у кнопки не может быть
размеров S и XS — таких не рекомендует ни Material, ни Angular, ни iOS»).

## Артефакты и где они лежат

| Что | Путь |
|---|---|
| Генератор | `DS/_audit/rec/build.py` — читает `data/*.json`, пишет страницы |
| Данные по компоненту | `DS/_audit/rec/data/<slug>.json` (один файл = один компонент) |
| Страницы (то, что смотрит пользователь) | `DS/components-mobile/prototypes/recommendations/{index.html,<slug>.html}` + `rec.css`, `rec.js` |
| Кэш исследований платформ | `DS/_audit/platform/<slug>.json` (по одному на компонент) |
| Реальные значения ДС из CSS | `DS/_audit/ds-css-values.json` |
| Каталог компонентов из спеки | `DS/_audit/spec-catalog.json` |

Относительные ссылки со страницы `prototypes/recommendations/x.html`: библиотека —
`../../../components-web/{font,tokens,styles}.css` + `components/index.css`, режим — `../../modes.css`.
Порядок подключения тот же обязательный (font → tokens → modes → components).

## Структура страницы — ПРОСТАЯ (сложную владелец отклонил)

Первая версия страницы была наоборот слишком техничной (токены, замеры, таблицы источников,
блоки «что рекомендуют платформы») и получила: «Очень много лишнего на странице, очень. Не всё
нужно выводить… Мне просто нужен мобильный компонент с отличиями от десктопного. И что в нём
меняется… Вся техническая инфа не нужна чтобы её выводить». Итоговый формат — 4 блока:

1. **Панели рядом** — `Desktop` (`data-mode="desktop"`) и `Mobile` (`data-mode="mobile"`),
   один и тот же markup, в шапке панели подпись с высотой («высота 36 px» / «высота 44 px»).
2. **Что меняется на мобиле** — таблица в три колонки Что / Desktop / Mobile.
   Строки: высота, паддинги, кегль, иконка, **наведение (hover)**, цвета/типы, размеры.
3. **Почему так** — 1–2 фразы простыми словами (палец вместо курсора, минимальная тач-зона),
   без ссылок и цитат.
4. **Итог** — что остаётся, что убираем, и отдельными пунктами «**Не решено:** …» — решения
   владельца (кегль, радиус, гасить ли hover на тач).

Категория изменения — тремя словами («Только размеры» / «Размеры + поведение» / «Структура»)
пилюлей под заголовком компонента.

Чего на странице быть НЕ должно: токенов, расчётов `calc`, таблицы замеров, ссылок на CSS,
карточек платформ, внутренних путей `_audit/…`.

### Схема данных (текущая)

`data/<slug>.json`: `component`, `ds_page`, `desc_ru`, `category_ru`, `category_note_ru`,
`summary_ru`, `panels.{desktop,mobile}.sub_ru`, `changes[] = {what, desktop, mobile}`,
`behaviour_html`, `why_ru`, `why_sources[]` (сейчас пусто — ссылки не выводим), `result_html`,
`examples[] = {title_ru, html, html_mobile?, stack?}`. Техническая часть (токены, платформы,
цитаты, замеры) — `data-tech/<slug>.json`, на страницу не попадает.

### Где теперь замеры

Страница больше не рендерит таблицу замеров (и `rec.js` из генератора убран). Если нужны
числа — отдельная временная страница с тем же markup и `data-measure`-JS, рендер headless
Chrome (`iiko-ds-components/scripts/headless-measure.py`). Так проверено: Desktop
`h=36 pad=8/12 font=14px/500`, Mobile `h=44 pad=12/16 font=16px/500`. В репозиторий такую
страницу не коммитить.

## Где брать рекомендации (проверенные пути)

- **m3.material.io** — клиентский рендер, curl отдаёт HTML без цифр.
- **material-web (официальные исходники M3 в вебе), читается curl-ом**:
  - значения компонентных токенов: `https://raw.githubusercontent.com/material-components/material-web/main/tokens/_md-comp-<component>.scss`
    — например `_md-comp-outlined-button.scss`: `'leading-space': … 24px`, `'trailing-space': … 24px`;
  - тач-таргет: `.../button/internal/_touch-target.scss` → `height: max(48px, 100%)`;
  - список полей токенов: `.../tokens/versions/v0_192/` (листинг через `api.github.com/repos/<repo>/contents/<dir>`;
    старые пути вида `tokens/versions/v0_192/md-comp-filled-button.scss` отдают 404 — имя всегда с `_`);
  - доки по компоненту: `.../docs/components/<name>.md`.
- **Angular Material**: доки и механика — markdown/scss в репозитории:
  `https://raw.githubusercontent.com/angular/components/main/src/material/<dir>/<file>.md|.scss`
  (например `button/button.md` — «minimum touch-target of 48x48 … particularly on mobile devices»;
  `button/button.scss`, `button/_button-base.scss` — отдельный `.mat-mdc-button-touch-target`, density его не сжимает).
- **iOS HIG** (`developer.apple.com/design/human-interface-guidelines/…`) — страницы
  тоже клиентские: curl возвращает ~17 КБ без текста (только SVG-пути). Числа HIG брать из
  уже снятого в проекте `Prototypes/compare-button-mob.html` (там таблица
  `Button_mob / MD3 / iOS` со ссылками) или из другого проверяемого источника; не выдумывать.
- Если `web_extract` отдаёт `403 Keyless Exa …` — не блокер: те же ссылки берутся
  через `curl -sL` в терминале.

## Как достать реальные значения ДС (без Figma)

- **Из компонентного CSS** (`components-web/components/<Имя>_DS/*.css`): перед регекспом
  **вырезать комментарии** — иначе комментарий приклеивается к селектору и ломает разбор;
  значения `var(...)` разворачивать по `tokens.css` (цепочки алиасов, до 12 уровней).
  Собирать `height / min-height / padding* / gap / font-size / line-height / border-radius`.
  Часто настоящие числа лежат ещё и в шапке файла («Трек 34×20 r12; кнопка (Oval) 16×16»).
  Готовый результат — `_audit/ds-css-values.json`.
- **Из спеки**: раздел `### Каталог компонентов Figma (все 106)` — блоки
  `#### <Имя> \`[id]\` — N вариантов` с описанием, строкой «Размеры: M (36px), S (28px), XS (24px)»
  и осями свойств (Size/Style/Type/State). До `### Карта классов CSS-библиотеки` (таблица
  «Компонент | Класс | Модификаторы»). Готовый результат — `_audit/spec-catalog.json`.
- Компонентные size-токены есть только у части библиотеки (`button`, `button-icon`, `chips`,
  `chips-input`, `form-field`, `search`) — для остальных числа берутся из CSS/спеки/замеров.
- Реальная разметка для примеров уже существует: страницы кита
  (`C:/Users/asukharev/GitHub/iiko-ds-kit/{button,checkbox,radio,input,chips,badge}.html`)
  и `Prototypes/metro-general-settings.html` (input, slide-toggle, dialog, banner,
  card, stepper) — копировать структуру оттуда, а не сочинять DOM.

## Объём работы: 37 компонентных папок

Рекомендации платформ собираются параллельно субагентами: 8 задач × ~5 компонентов,
у каждой контракт «по одному JSON на компонент в `_audit/platform/<slug>.json`» с полями
`exists / sizes[{name,value,quote,source}] / variants / touch_target / notes_ru / sources`,
плюс `not_recommended_ru` и `verdict_ru`. В контекст задачи обязательно писать:
только первоисточники, каждое число — со ссылкой и короткой цитатой, нет источника → `null`
и «не найдено», ничего не придумывать, файлы создавать (`mkdir -p`). Свод возвращается
одним сообщением, когда закончат все.

## Оболочка: меню компонентов слева + iframe (build.py)

Пользователь попросил: «Переделай эту страницу — сделай левое меню с компонентами, при клике на пункт
меню выводится соответствующая страница». Реализовано в генераторе, не в готовом HTML:

- `index_page(all_data)` собирает оболочку: `nav.nav` с кнопками `data-slug` из `data/*.json`
  (новый компонент появляется в меню сам после `python build.py`) + `<iframe class="frame" id="frame">`.
- JS: `activate(slug)` — подсветка активного пункта, `src` фрейма, `location.hash`; на старте читается хэш
  (`index.html#button-toggle` — рабочая ссылка на конкретный компонент), есть `hashchange`.
- Высота фрейма подгоняется по `contentDocument.documentElement.scrollHeight` на `load` и `resize`
  (внутреннего скролла нет — скроллится вся оболочка); меню `position: sticky`, на <900 px — `static`.
- Внутри оболочки у страницы компонента скрывается ссылка «← Все компоненты»: same-origin → в `<head>`
  фрейма добавляется `<style id="embedded-fix">.crumbs{display:none}</style>` в `try/catch` (на `file://`
  доступ к `contentDocument` запрещён — тогда остаётся CSS-фолбэк).
- В самих страницах компонентов «← Все компоненты» ведёт на `index.html#<slug>` (в `page()` добавлен `slug`).

**Ширина.** Владелец сказал «Сделай страницу шире» — `.wrap` теперь `width:100%; max-width:100%`
(страница на всю ширину минус поля `body`), меню 260 px, зазор 20 px; сплошной текст остаётся в читаемую
меру: `.point` и `ul.list` — `max-width: 1100px`, панели и таблицы на всю ширину. Замерено: окно 1920 →
страница 1839, панель 746, таблица 1477; окно 1440 → 1344 / 498 / 982.

**Как это проверять (headless, без запроса прав на отладку).**

- Разметка и активный пункт: `--dump-dom` по `index.html` и по `index.html#<slug>` — видно `src` фрейма,
  `class="nav__item is-active"` и вычисленную `style="height: …px"`.
- **Живой клик** проверяется только с http-страницы: временный файл-обёртка в корне DS (отдаётся тем же
  сервером 8899), внутри `<iframe src="…/index.html">`, из родителя `contentDocument` →
  `items[2].click()` → прочитать `is-active`, `src` фрейма, хэш и наличие `#embedded-fix` у внутреннего
  документа; результат писать в `document.title`, читать `--dump-dom`, обёртку удалить. Так подтверждено:
  было `button / button.html` → стало `button-toggle / button-toggle.html`.
- У сгенерированных страниц нет `data-measure`: probe-копия в той же папке + скрипт, пишущий JSON в
  `document.title`; `--dump-dom`; probe удалить.
- Интерактивный браузер (`browser_exec`) для этого не нужен и просит у пользователя галочку
  «Allow remote debugging» — headless делает то же самое без клика по галочке.

## Поведение с пользователем (важно)

- **Не сравнивать с Figma и не смотреть на собранные `_mob`-компоненты, если он этого
  не просил.** Его формулировка: «Сейчас вообще не нужно смотреть на созданные мобильные
  компоненты в фигме. И сравнивать ничего не нужно.» Рекомендации платформ — источник,
  Figma — потом.
- **Не отвечать одним уточняющим вопросом.** Когда он повторил задание после ответа,
  который состоял только из вопросов, это читается как отказ работать. Если трактовка
  неоднозначна, но есть очевидный дефолт — делать по дефолту, явно перечислить допущения
  и назвать, что поменять, если формат не тот.
- Формат подачи: что сделано (путь), что проверено (числа с браузера), что дальше —
  и ни слова про процесс.
- **Ссылки.** `file://` в ACP-панели не открывается (и markdown-ссылка на него тоже):
  поднимать `python -m http.server 8899 --bind 127.0.0.1 --directory C:/Users/asukharev/GitHub/iiko-DS/DS`
  и либо давать полный http-адрес текстом, либо сразу открывать браузер самому
  (`cmd.exe /c start "" "http://127.0.0.1:8899/<путь>"`). См. SKILL.md, «Как отдавать ссылку».
