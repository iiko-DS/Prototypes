# Аудит файлов рабочего дерева («все ли файлы нам нужны»)

Замеры и находки 15.09.2026, после разбора структуры. Владелец: «А все ли файлы нам нужны или от
чего то можно отказаться или наоборот добавить?» — это отдельный класс задачи: инвентаризация
**своего** дерева, а не разбор чужого репозитория (тот — `reports-as-files-and-external-repo-reviews.md`).

Правило, которое связывает всю работу: **сам ничего не удаляю и не «чищу»**. Отчёт = список с
доказательствами, работы — после его слова (тот же урок, что с прототипами: «Не удалять прототипы/демо
и не „чистить“ ссылки по своей инициативе»). В отчёте это отдельная плашка внизу.

## 1. Что мерить (три замера, все read-only)

### а) Ссылочный анализ: кто вообще упомянут

Для каждого файла — упоминается ли его **базовое имя** в любом другом текстовом файле
(`.html/.css/.js/.mjs/.py/.md/.json/.txt/.ps1/.svg/.yml/.xml`). Отдаёт список «нигде не упомянутых».

⛔ **«Нигде не упомянут» ≠ «не нужен».** Ложные срабатывания именно там, где и интересно:
- PNG и сырьё (`_audit/platform/_raw`, `_src`) читаются скриптами **через glob по каталогу**, а не по имени;
- поэтому вердикт даётся только после поиска потребителя двумя способами: по имени файла и по каталогу
  (`open(`, `glob`, `import`, `pathlib.Path`), плюс по расширению рядом;
- страницы сознательно берут часть библиотеки мимо агрегатора (`build.py:774-780` подключает четыре CSS
  Checkbox/Radio явно) — «нет в агрегаторе» тоже не значит «не используется».

### б) Дубли по содержимому

`hashlib.md5` по файлам >1 КБ → группы одинаковых. В нашем дереве так нашлись 32 группы: одни и те же
PNG лежат в трёх местах (корень `_crops/`, `iiko-ds-prototypes/_crops/`, `_audit/`), плюс совпадающие
markdown-выгрузки в `platform/_raw` ↔ `platform/_src`.

### в) Вес в git

`git ls-files` → `os.path.getsize` по каждому пути → сумма по первым двум сегментам.
⛔ **Не считать через `git cat-file -s` на каждый файл**: на 1167 файлах это упирается в таймаут
терминала (180 с) и не отдаёт ничего. `git ls-files` + размеры на диске отвечают за секунды
(+ `git count-objects -vH` для размера самого пака).

Готовый прогон всех трёх замеров — `scripts/audit-repo-files.py`
(`python scripts/audit-repo-files.py --root C:/Users/asukharev/GitHub/DS`).

## 3. Форма ответа (в чат и в PDF)

1. Короткий вывод первым: «ядро нужно целиком, отказаться можно примерно от десяти позиций, и все они —
   рабочие артефакты, а не дизайн-система».
2. **A. Нужно, трогать не надо** — списком, с числами (что именно защищаем: компоненты, мобильный слой,
   страницы, данные, проверки, сырьё под цитаты).
3. **B. От чего можно отказаться** — таблица: что · вес · **доказательство** (нулевой grep, совпавший MD5,
   `14 Б = 404: Not Found`) · риск отказа. Каждая строка опровержима, без «кажется, не нужно».
4. Отдельной плашкой — «не отказ, а наоборот» (у нас: четыре CSS Checkbox/Radio мимо агрегатора;
   правка в `iiko-ds-web` — только с его слова).
5. **C. Что стоит добавить** — таблица: что · **доказательство отсутствия** (файла нет, ни одного workflow,
   `data-theme` 0 вхождений), а не «было бы неплохо».
6. «Что предлагается первым делом» — 1–3 пункта.
7. Плашка: «Ничего не удалялось и не менялось — это отчёт. Удаление и правки — после отдельного
   подтверждения».

Границы наших правок держать в голове прямо в отчёте: `iiko-ds-web` — не трогать без прямого разрешения,
снятие файлов с версионирования — тоже отдельное решение, а не следствие аудита.
