# База знаний команды ДС

Здесь два больших раздела — **дизайн-система** и **прототипы** — и всё, что помогает с ними работать: как начать, рецепты, правила для ИИ-агентов, аналитика, журнал решений.

| Папка | Что внутри |
|---|---|
| [`01-start/`](01-start/) | с чего начать: доступ в организацию, установка, клонирование, запуск |
| [`02-design-system/`](02-design-system/) | **дизайн-система**: что это, из чего состоит, где лежит, как её применять |
| [`03-prototypes/`](03-prototypes/) | **прототипы**: что это у нас, где лежат, из чего собираются, как показываем |
| [`04-process/`](04-process/) | процесс и договорённости: как вместе работаем, что за чем идёт |
| [`05-howto/`](05-howto/) | рецепты на каждый день: поправить значение, обновить базу, предложить правку |
| [`06-agents/`](06-agents/) | правила и скиллы для ИИ-агентов (Copilot, Claude, Hermes) |
| [`07-research/`](07-research/) | аналитика: замеры, разборы, сравнения, исследования поведения |
| [`08-decisions/`](08-decisions/) | журнал решений: что решили и почему, чтобы не решать одно и то же дважды |
| [`09-archive/`](09-archive/) | устаревшее: не удаляем, складываем с пометкой |

Порядок чтения для нового человека: `01-start` → `02-design-system` → `03-prototypes` → дальше по надобности.

## Где лежит сама дизайн-система

| Репозиторий | Что это |
|---|---|
| [`iiko-ds`](https://github.com/iiko-DS/iiko-ds) | генератор страниц, данные компонентов, `serve.py` — с него начинается работа |
| [`iiko-ds-web`](https://github.com/iiko-DS/iiko-ds-web) | десктопный слой: компоненты, токены, стили, спецификация `iiko-ds-spec.md` |
| [`iiko-ds-mobile`](https://github.com/iiko-DS/iiko-ds-mobile) | мобильный слой ДС |
| [`iiko-ds-prototypes`](https://github.com/iiko-DS/iiko-ds-prototypes) | прототипы экранов (в том числе KDS) |

Этот репозиторий — база знаний: он ничего не собирает и ни от чего не зависит, читается прямо на GitHub, клонировать рядом с ДС не обязательно.

## Как добавить сюда своё

1. Ветка: `имя/что-делаю`, например `ivan/howto-dialog`.
2. Правка.
3. `Push origin` → `Create Pull Request` в `main`.

Подробно — [`04-process/совместная-работа.md`](04-process/совместная-работа.md). Коротко: в `main` напрямую не пишем, потому что на бесплатном плане ветку технически защитить нельзя и вся защита держится на договорённости.

**Правило пополнения:** каждый раз, когда объясняешь коллеге одно и то же в чате, здесь должно появиться на страницу больше. Если объяснение было полезным — оно стоит того, чтобы его не повторять.
