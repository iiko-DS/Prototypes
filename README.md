# Как мы работаем с дизайн-системой iiko

Этот репозиторий — **не описание дизайн-системы**. Он про путь: как из дизайн-системы получаются прототипы экранов, и что нужно знать, чтобы собирать их качественно и одинаково.

- **Дизайн-система** — вход: компоненты, токены, спецификация.
- **Прототипы** — результат: страницы и стенды, которые показывают заказчику и по которым потом делают продукт.
- **Правила, рецепты, аналитика, решения** — то, что делает результат лучше с каждой итерации.

Всё вместе — это один большой сценарий «взяли задачу → собрали прототип из ДС → показали → договорились → перенесли в общее».

## Где лежит сама дизайн-система

| Репозиторий | Что это |
|---|---|
| [`iiko-ds`](https://github.com/iiko-DS/iiko-ds) | генератор страниц, данные компонентов, `serve.py` — с него начинается работа |
| [`iiko-ds-web`](https://github.com/iiko-DS/iiko-ds-web) | десктопный слой: компоненты, токены, стили, спецификация `iiko-ds-spec.md` |
| [`iiko-ds-mobile`](https://github.com/iiko-DS/iiko-ds-mobile) | мобильный слой ДС |
| [`iiko-ds-prototypes`](https://github.com/iiko-DS/iiko-ds-prototypes) | прототипы экранов (в том числе KDS) |

Этот репозиторий — база знаний: он ничего не собирает и ни от чего не зависит, читается прямо на GitHub, клонировать рядом с ДС не обязательно.

## Как добавить сюда своё

1. Ветка: `имя/что-делаю`, например `ivan/howto-dialog`.
2. Правка.
3. `Push origin` → `Create Pull Request` в `main`.

Подробно — [`03-rules/`](03-rules/). Коротко: в `main` напрямую не пишем, потому что на бесплатном плане ветку технически защитить нельзя и вся защита держится на договорённости.

**Правило пополнения:** каждый раз, когда объясняешь коллеге одно и то же в чате, здесь должно появиться на страницу больше. Если объяснение было полезным — оно стоит того, чтобы его не повторять.
