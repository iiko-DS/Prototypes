# Поправить значение компонента

Когда нужно: компонент выглядит не так — отступ, размер, цвет, текст, вариант состояния.

## Что важно понять сразу

**Страницы генерируются.** HTML в `iiko-ds-mobile/prototypes/recommendations/` собирается скриптом из данных — руками его править нельзя, при следующей сборке правка исчезнет. Всё, что видно на странице, правится в данных.

## Порядок

1. Обновить базу, чтобы правка не потерялась: `python pull.py`.
2. Завести свою ветку (`Current Branch → New Branch`, имя `ivan/badge-fix`). В `main` не пишем — почему, в [правилах](../02-rules/README.md).
3. Найти нужный файл данных:
   - **значение на странице компонента** — `_audit/rec/data/<компонент>.json` (имя файла = имя страницы, например `badge.json`);
   - **технические заметки** (источники, платформа, замеры) — `_audit/rec/data-tech/<компонент>.json`;
   - **мобильные значения** — `_audit/platform/<компонент>.json`, а если правка касается мобильного CSS — в `iiko-ds-mobile/components/…`.
4. Изменить значение. Если правка касается внешнего вида десктопа — CSS живёт в `iiko-ds-web/components/<Имя>_DS/*.css` (это отдельный репозиторий, но в той же папке рядом).
5. Пересобрать и посмотреть: `python start.py`, обновить страницу в браузере.
6. Описать правку в коммите по-человечески: что и почему. «Поправил отступ» хуже, чем «Badge: отступ 4 → 8, по спецификации ДС».
7. `Push origin` и Pull Request в `main` — по [рецепту «предложить правку»](03-предложить-правку.md).

## Частые ошибки

- Правили сам `html` вместо данных — правка пропала после сборки. Возвращаем: `git checkout`, дальше правим `data/*.json`.
- Правили значение в двух местах (данные и собранная страница) — оставляем только данные.
- Значение в `_audit/platform/*.json` меняли руками, но оно пересобирается скриптами из `_audit/platform/_src/` — если правишь регулярно, скажи владельцу, поправим в источниках.
